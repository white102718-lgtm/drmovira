# 飞书组织自动同步

## 部署顺序

1. 停止旧版本的组织同步入口和正在进行的任务。
2. 人工审核并执行 `adpulse-system/src/main/resources/db/migration/V39__schedule_feishu_organization_sync.sql`。脚本只执行一次；应用不会自动建表。脚本将旧版本未结束日志标记失败，避免占用新活动槽。
3. 部署后端和配套前端。`/preview` 和 `/sync` 的响应结构已改变，应配套发布。
4. 在组织架构同步页生成预览，核对差异，再保存开启自动同步的配置。首次默认关闭、每小时一次，缺失保护默认为10条或20%。

本次代码交付不执行环境数据库脚本，不自动开启计划，也不触发真实通讯录写入。

## 操作与权限

- 查看配置、日志、预览需要 `system:department:list` 和 `system:user:list`。
- 保存应用配置、计划和提交任务另外需要 `system:department:update` 和 `system:user:update`。
- 支持每15、30、60分钟及每天指定北京时间；计划时间以UTC保存，接口返回北京时间偏移。
- 启用或修改启用中的计划，需要当前用户15分钟内、同一应用配置的成功预览。关闭计划不需要预览，也不会取消已提交任务。
- 人工任务要求有效预览；预览绑定应用、远端完整快照和本地启停基线。实际执行时有变化则不写入，要求重新预览。
- 部门、人员缺失分别按现有启用记录计算，数量或比例达到阈值即拦截整次写入。明确返回停用的人员不视作范围缺失，但计入停用统计。
- 自动任务触发保护时标记 `REVIEW` 并关闭自动计划。核查飞书可见范围后重新预览；人工确认只对当前预览有效。同步后重新预览并开启计划。
- 空人员快照、部门循环、父级或人员部门不在同步范围等结构问题不能通过人工确认绕过。
- 同步只维护飞书来源的组织字段，不修改本地用户、角色和数据权限关系。

## 接口变化

- `POST /feishu/organization/preview`：返回 `{ previewId, result, requiresReview }`。
- `POST /feishu/organization/sync`：请求 `{ previewId, acceptMissing }`，返回 `{ id, status: "PENDING" }`；响应仅表示提交成功。
- `GET /feishu/organization/schedule`：查询配置。
- `PUT /feishu/organization/schedule`：`enabled`、`intervalMinutes`（0/15/30/60）、`dailyTime`（HH:mm）、`missingCountLimit`、`missingPercentLimit`、`previewId`。
- `GET /feishu/organization/logs`：最近100条预览及任务记录；状态包括 `PENDING/RUNNING/SUCCESS/FAILED/REVIEW/SKIPPED`；`SCHEDULED`来源的`startedBy`为空。

## 执行与恢复

- 独立两线程调度器：每分钟检查到期计划，每5秒认领任务。只注册组织任务，不开启系统服务中其他尚未启用的注解调度。
- 计划单行 `FOR UPDATE` 锁串行化状态迁移，日志生成列唯一索引保证最多一个活动任务，支持多个服务实例。
- 网络拉取不占数据库事务；写入前在计划行锁内核验任务状态、执行次数和租约。组织变更与成功日志在同一事务提交。
- 连接/读取超时为10/30秒，完整快照读取预算10分钟，任务租约15分钟，写入事务预算120秒。
- 临时连接错误、HTTP 5xx和429最多执行三次，间隔30/120秒；业务校验和数据库写入失败不重试。
- 超时或进程中断由下一轮扫描标记失败；旧执行线程不能覆盖已恢复的任务。停机错过的多个周期只补一次，已有活动任务时记录跳过，不积压。
- 界面轮询显示状态；无外部消息通知。数据库和飞书端到端验收应在应用V39后的测试环境进行。
