# 投放日报

本模块属于 main 服务，提供本人按日查询、填写、补录和保存，不创建审批申请、不发送审批通知，不保存平台消耗快照。

## 数据口径

- 服务端从会话解析用户ID，读取 `sys_user.english_nickname` 匹配 Doris `placer_id`。不接受客户端指定他人的英文名或用户ID。
- Doris `internal.ad.ad_daily_detail` 只取 `level = 'campaign'`；日期直接使用 `date`，不另行转时区。
- 按日期、`game_platform`（项目名称）、`agent_line`（代理线名称）、`placer_id` 和 `ad_platform` 聚合。平台统一小写。
- 用项目名和代理线名同时精确匹配 `pm_project` 与 `pm_agency_line`。没有匹配或匹配多条的组不展示，响应返回未匹配组数。
- 最终日报唯一键为本人ID、日期、项目ID、代理线ID、平台；英文名修改不改变已保存记录的归属。

| 日报字段 | Doris字段及行为 |
| --- | --- |
| 实际消耗 | `ROUND(SUM(CAST(amount_spent AS DECIMAL(18,4))), 2)`，USD，只读，每次刷新取最新值，先聚合再四舍五入至两位 |
| 日报消耗 | 首次默认等于实际消耗；保存后优先使用人工值 |
| 展示 | `SUM(impressions)` |
| 点击 | `SUM(clicks_all)` |
| 账户内安装 | `SUM(app_installs)` |
| 账户内注册 | `SUM(complete_registration)` |
| 账户内首购 | `SUM(purchases)`，2026-09-10 用户确认此业务口径 |
| 来源 | `COLLECT_SET(account_id)`、`COLLECT_SET(campaign_id)`，去重保存 |
| 调整额、二次核减、承担类型、备注 | 人工填写，所有金额输入、保存和回显统一两位小数 |

含回流消耗按“实际消耗 - 调整额”计算；调整额为负数时，等价于实际消耗加上调整额的绝对值。回流增加额：实际消耗 - 日报消耗。二次核减单独记录，本次不引入绩效核算公式。无平台数据时实际消耗为0.00，含回流消耗等于调整额的相反数，回流增加额等于日报消耗的相反数。手工行编辑能力使用独立标记，不以消耗是否为零判断。

取数失败时明确报错，不能把故障当作零消耗。已保存内容与当日平台数据按唯一键合并，补到的平台数据更新手工行实际消耗，保留人工指标和截图。

## 接口

接口均使用 main 服务现有认证与Redis会话校验：

- `GET /delivery-reports?date=YYYY-MM-DD`：读取本人数据及未匹配组数。
- `GET /delivery-reports/options`：提供有效项目、代理线的ID组合供补录选择。
- `PUT /delivery-reports`：传 `date`、`rows`；每行仅允许写项目ID、代理线ID、平台、固定人工指标和 `attachmentIds`，不接收平台实际消耗与来源ID。

截图复用 system `/files/upload` 和带认证的下载接口。每行最多5张，支持PNG、JPEG、WebP、GIF、选择上传与剪贴板粘贴。保存时校验文件存在、当前上传人、类型和数量。移除截图只解除日报关联；已关联文件禁止直接删除。

前端日报列表仅回显已保存记录，不提供修改入口；填写页允许修改所选日期的历史已填记录，保存按钮同时保存新行和历史行。日期和平台实际消耗仍只读。截图列仅展示数量和“查看”入口，点击后才在弹窗加载图片；填写页可上传、移除新行和历史记录的截图，列表仅允许查看。

旧浏览器缓存及旧审批申请不会自动迁入新日报表；新版填写入口不再创建审批。绩效tab当前展示本人已保存日报的基础明细，不提供绩效审核或计算公式。

## 绩效报表

- `GET /delivery-reports/performance?startDate=YYYY-MM-DD&endDate=YYYY-MM-DD` 按闭区间查询当前会话用户的已保存日报，返回逐日明细及当前主部门（未设置时显示“未设置”）。不扩大现有本人数据权限。
- 绩效页默认本月，按所选时间段、项目ID、投放师ID汇总；跨代理线和平台合并，代理线、平台、调整承担展示去重值，数值字段求和，金额按分累加后显示两位小数。
- 开始日期、结束日期采用查询区间；实际消耗沿用日报最新平台值，缺失按零处理，含回流消耗和回流增加额沿用日报公式。
- 绩效页无统计看板、代理线筛选、备注和截图列。右侧固定“展开”打开关联的逐条日报，复用日报字段和截图弹窗，保持只读。

## 日报与绩效的查看权限

- `AM`、`OPERATOR_LEADER`、`ADMIN` 任一角色允许查看所有未删除人员的已填日报；其他用户仅限本人。角色以 Redis 会话的 `ROLE_*` authority 为准。
- `GET /delivery-reports/reporters` 返回有权查看的人员；`GET /delivery-reports/read?date=...&reporterId=...` 返回只读逐条日报；绩效接口同样支持可选 `reporterId`。不传人员时按权限汇总，普通用户仍限定本人，主动请求他人ID则拒绝。
- 部门按每条结果的投放师所属主部门返回。展开明细与截图下载采用相同的查看范围。
- 填写查询和 PUT 保存始终使用当前会话本人身份；管理角色不会获得替他人填写、修改或删除截图的权限。
- 本次仅修改代码，未启动或重启本地服务。生效需由开发者加载更新后的 main 与 system 服务。

### 人员导航筛选

日报与绩效“按人看”仅列出具有有效 `OPERATOR` 角色的未删除用户，并叠加查看范围：普通用户至多列出本人，管理角色列出所有投放师。无匹配人员时显示空状态，不再自动补入非投放师的当前用户。此筛选只作用于人员导航，不改变已确认的汇总查看和本人填写权限。

## 汇总查询性能优化

- 日报列表使用 `GET /delivery-reports/page`：日期、人员范围、姓名/项目/代理线筛选在 MySQL 中先过滤，再执行稳定排序和分页；每页上限100条。人员与主部门直接联表读取。
- 统计使用独立的 `GET /delivery-reports/stats`，与列表使用同一筛选条件，翻页不重新取统计；统计失败可单独重试，不阻塞列表展示。
- 平台实际消耗按当前记录涉及的英文名去重后批量查询（每批最多200人），按日期、人员、项目、代理线、平台分组，只查询消耗，不再读取大量账户和Campaign来源集合。平台故障仍报错，不把故障当作零消耗。
- 截图按当前页日报ID批量读取；统计不读取截图。绩效时间段接口同样复用批量读取逻辑，避免按人员、日期循环访问数据库。
- 空页无平台请求；普通用户的分页、统计、绩效全部在后端限制本人。管理角色的汇总范围维持原有规则。

## 投放日报列表时间段

- `/delivery-reports/page` 与 `/delivery-reports/stats` 使用 `startDate`、`endDate`（YYYY-MM-DD），包含首尾日期；允许起止同日，拒绝缺失或倒置区间。
- 列表默认昨天至昨天，仍按每条日报的实际日期展示，不跨天合并。统计覆盖同一筛选区间，翻页沿用已查询区间。
- 填写页的查询与保存仍是单日 `date`，不受列表时间段调整影响。

## 投放师填写入口

日报类型可见性及填写入口由规则人员配置控制，不根据 OPERATOR 或管理角色自动开放。投放日报需将投放师角色加入填写人，绩效报表需加入查看人。既有本人/全员数据查看范围保持不变。

## 写入项目Google日报

- “项目日报模板”“推送记录”“填写到项目日报”及其后端接口统一要求`workbench:daily:report:push`权限；无权限用户不展示按钮和表格勾选入口，直接请求接口也会被拒绝。
- 一个有效项目只能配置一个Google日报模板；日报推送使用独立Google服务账户，保存Spreadsheet、Sheet及固定日报字段到目标列的映射。原Google数据同步仍使用用户OAuth，互不影响。
- 配置模板时选择项目后，系统解析`pm_project.customer_daily_report_url`中的Spreadsheet ID和`gid`，并通过日报服务账户验证访问权限后自动确定表格与页签；两者只读且不能手动修改。链接未配置、格式无效、未指定`gid`、目标页签不存在或服务账户无法访问时直接拒绝保存；链接目标仍须共享给服务账户。
- 模板项目下拉复用`GET /delivery-reports/options`，只展示同时存在有效代理线的有效项目；项目和代理线均未删除才可配置日报模板。
- 模板需从已映射字段中选择一列或多列作为联合唯一键，例如“日期 + 项目名称 + 媒体平台”。目标行所有唯一字段同时相同时更新原行，否则追加新行；唯一字段为空、目标表存在重复组合或同批日报产生重复组合时拒绝推送，避免误更新。
- 首条数据写入第2行时清除该行继承自表头的用户格式，避免出现加粗和表头背景色；第3行及以后不修改表格既有格式。
- 旧模板未保存联合唯一键时，读取时暂以原`reportId`映射兼容；用户重新编辑并保存模板后，改用所勾选的唯一字段组合。系统不再自动创建、改名或隐藏记录ID列。
- 日报列表允许选择当前页一条或多条已保存记录。服务端按原有日报查看范围重新读取记录，并按项目拆分到各自模板；任一项目缺少有效模板时，预览和确认均整体拒绝。
- 确认后固化当前平台消耗、人工指标和模板目标的写入快照，后台批次逐条执行。跨项目部分失败不会回滚已经写入Google的数据，失败明细可重试。
- 目标Spreadsheet必须以编辑者身份共享给服务账户邮箱；模板下拉框只列出服务账户有权访问的原生Google Sheets文件。
- 服务账户凭据通过`GOOGLE_DELIVERY_SERVICE_ACCOUNT_CREDENTIALS_FILE`或`GOOGLE_DELIVERY_SERVICE_ACCOUNT_CREDENTIALS_BASE64`注入，不得提交到仓库或记录到日志。
- 已部署V47的环境需在发布代码前依次人工执行`adpulse-main/src/main/resources/db/migration/V48__use_service_account_for_delivery_report_google_push.sql`和`V49__use_configurable_delivery_report_unique_keys.sql`；全新环境直接执行更新后的V47。本功能不推送截图，不提供定时自动推送。
