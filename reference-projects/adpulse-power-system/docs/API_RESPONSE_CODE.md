# API 响应码规范

前端落地实现、Axios/Vben 拦截器示例及验收清单见 [前端统一接口响应处理规范](FRONTEND_API_RESPONSE_INTEGRATION.md)。

## 1. 响应结构

所有接口统一返回：

```json
{
  "code": 200,
  "message": "success",
  "data": null
}
```

`code` 是三位业务响应码。凡请求已经到达应用并由 Spring MVC 或 Spring Security 正常生成响应，无论成功、业务异常、认证失败还是未预期异常，HTTP 状态码都固定为 `200`。前端只能依据响应体 `code` 判断业务结果。

网关不可用、连接超时、服务进程退出等未进入应用响应流程的故障，不受本规范控制，前端仍需保留网络异常处理。

## 2. 号段与展示策略

| 号段 | 含义 | 前端默认行为 |
| --- | --- | --- |
| `2xx` | 成功 | 正常读取 `data` |
| `4xx` | 流程型错误 | 全局静默，不弹通用错误；由登录、MFA、权限等业务页面处理 |
| `5xx` | 可展示业务错误 | 使用 `message` 向用户展示警告或错误提示 |
| `6xx` | 系统错误 | 全局静默，不展示后端细节；记录日志并展示固定兜底文案（如“系统繁忙，请稍后重试”） |

前端可按以下方式判断：

```ts
const family = Math.floor(code / 100);

if (family === 2) return data;
if (family === 4) throw new SilentApiError(code, message);
if (family === 5) showError(message);
if (family === 6) {
  reportError(code, message);
  showError('系统繁忙，请稍后重试');
}
```

这里的“静默”只表示禁止全局错误拦截器直接弹出后端 `message`。对应页面仍可根据具体响应码展示安全、明确的页面内提示。

## 3. 当前响应码

| code | 含义 | 前端建议 |
| --- | --- | --- |
| `200` | 成功 | 读取 `data` |
| `400` | 登录认证失败 | 登录页展示安全提示 |
| `401` | JWT 或 Redis 会话无效 | 清理登录状态并跳转登录页 |
| `403` | 权限不足 | 跳转 403 页面或在当前页面处理 |
| `410` | MFA 挑战无效或过期 | 清除挑战并返回密码登录页 |
| `411` | MFA 挑战用途不匹配 | 清除挑战并返回密码登录页 |
| `412` | MFA 状态发生变化 | 清除挑战并重新登录 |
| `413` | MFA 动态码错误、过期或已使用 | 停留当前 MFA 页面并允许重试 |
| `414` | MFA 尝试次数过多 | 清除挑战并返回密码登录页 |
| `500` | 通用可展示业务错误 | 展示 `message` |
| `501` | 参数或查询条件校验失败 | 展示 `message`，表单场景可定位字段 |
| `502` | 数据重复 | 展示 `message` |
| `503` | 资源不存在 | 展示 `message` |
| `504` | 当前业务状态冲突 | 展示 `message` |
| `600` | 未预期系统异常 | 不展示后端 `message`，上报并使用固定兜底提示 |

## 4. 后端开发约束

- 禁止新增四位或五位响应码，`ApiResponse` 会在运行时拒绝非三位码。
- 禁止业务代码根据异常类型修改 HTTP 状态码，所有应用层响应统一为 HTTP 200。
- 响应码必须在 `ApiCode` 中集中声明，不允许在业务代码中散落数字字面量。
- 可预期且允许用户看到的业务异常使用 `BusinessException.validation`、`notFound` 或 `conflict`。
- 登录、会话和 MFA 流程使用 `4xx` 常量，由对应前端流程自行处理。
- 未捕获异常统一转换为 `600`，真实异常仅写入服务端日志。
- 新增响应码时必须同步本文件、接口测试及前端拦截器规则。
