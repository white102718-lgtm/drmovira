# AdPulse AI 代码与数据库规范

本文件是 AdPulse 代码生成、修改、重构、评审和数据库设计的权威规范。前端视觉与交互规则只在 `ui-guidelines.md` 维护；工程执行、环境、验证和发布规则只在 `engineering-workflow.md` 维护。

## 1. 使用方式与优先级

- 开始编码前完整阅读根目录入口文件和本文件；涉及 UI 时再完整阅读 `ui-guidelines.md`，涉及启动、跨仓、验证或交付时阅读 `engineering-workflow.md`。
- 冲突优先级：用户当前明确要求 → 根目录入口中的项目边界 → 对应专题规范 → 仓库工具配置 → 相邻稳定实现。
- 只修改当前需求及其可靠运行所必需的范围，保留无关行为、接口和兼容边界。

## 2. 通用编码原则

- 先确认业务流程、类型、权限、状态和边界条件，不猜测不存在的接口或字段。
- 命名直接表达业务含义；避免无意义缩写、魔法值、重复逻辑、过深嵌套和无调用的预留代码。
- 优先复用已有组件、Service、类型、工具和适配器；不为一次调用增加无价值封装。
- 不滥用 `any`、非空断言、`as unknown as`，不以类型断言掩盖契约问题。
- 不写空 `catch`，不吞异常，不把原始堆栈、SQL、令牌或服务端敏感信息展示给用户。
- 业务关系使用稳定 ID，不使用名称代替关联键；大整数 ID 始终按字符串处理。

## 3. 注释规范

- 注释解释业务规则、设计原因和不可随意修改的边界，不逐行翻译代码。
- 公共函数、公共类型、Composable、Store action、Service 方法及复杂组件输入输出优先使用中文 JSDoc。
- 金额、时区、权限、状态流转、并发、防抖、缓存、幂等、正则、复杂公式、迁移兼容和临时方案必须补充中文说明，并标明单位或触发条件。
- 删除注释掉的旧代码；待办事项须说明原因及负责人或解除条件，禁止孤立的 `TODO`。

## 4. TypeScript 与 Vue

- 使用 TypeScript 和 `<script setup lang="ts">`；遵循仓库 Prettier、ESLint、Stylelint 和 EditorConfig。
- Vue 单文件组件按 `<script setup>`、`<template>`、`<style scoped>` 排列；只有确有需要时添加局部样式。
- import、未使用代码和格式交由项目工具统一；复杂表达式拆成有业务含义的中间变量。
- 布尔变量使用 `is/has/can/should` 前缀；事件函数使用 `handleXxx`；加载函数使用 `loadXxx` 或 `fetchXxx`；ID 使用明确业务名。
- 单个函数只承担一个主要职责，优先提前返回。组件长期超过约 500 行、包含多个独立区域或出现可复用 UI 时再拆分，避免碎片化。
- 异步统一使用 `async/await`；`loading` 在 `finally` 恢复；可取消搜索、筛选和快速切换请求必须透传 `AbortSignal` 或使用请求序号。

## 5. API、组件与数据边界

- 业务代码默认只在 `plat/` 开发；页面位于 `plat/src/views/**`，接口按业务域位于 `plat/src/api/**`。
- 新功能先检索 `plat/src/views/components/` 和相邻模块。列表优先 `useVbenVxeGrid`，表单优先 `useVbenForm`，弹窗和抽屉优先 `useVbenModal` / `useVbenDrawer`。
- 页面负责展示与交互，Service 负责业务动作，Adapter 负责数据源及新旧结构兼容。
- API 层负责响应解包和通用错误提示，页面不重复判断状态码；需要自定义提示时传 `{ skipErrorMessage: true }` 并提供明确反馈。
- 接口参数与表单字段同名时直接传递，不创建无价值映射层。正式文案使用 `$t()` 并同步语言资源。
- 新增依赖前先确认现有依赖、浏览器能力或项目公共能力无法满足需求。

### 5.1 项目下拉接口

- 项目下拉禁止调用 `GET /project/projects`，也不得通过 `projectService.list()`、`projectService.listOptions()` 或 `getProjectOptionsApi()` 间接加载完整项目列表。历史调用不得作为新代码参考。
- 默认使用 `projectService.searchScopedOptions()`（`GET /project/projects/options/scoped`）遵循当前用户的数据范围。
- 只有业务明确允许跨数据范围时才使用 `projectService.searchOptions()`（`GET /project/projects/options`），并记录不隔离原因。
- 选项以项目 ID 为值、名称为展示。需要其他字段时按 ID 查询详情，或扩展轻量选项契约/专用接口，不得退回完整列表接口。
- `GET /project/projects` 仅用于项目管理列表及明确需要分页、筛选和完整读模型的非下拉查询。

### 5.2 列表页 URL 状态

- 仅菜单直接可见、以列表为主要内容且提供筛选的一级页面启用 URL 状态；详情、流程、隐藏旧入口、弹窗、抽屉和临时选择器不接入。
- 统一使用 `useListRouteState` 同步最后一次实际查询条件；分页列表还要同步 `page` 和 `page_size`。
- 初始化、刷新及浏览器前进/后退时，先校验并恢复 URL 状态，再请求列表；筛选、重置或每页条数变化后回到第一页。
- 搜索按钮页面在提交时写 URL；输入即查询页面随实际请求写入。同页多个主要列表使用独立 `scope`。
- 使用 `router.replace` 并保留 `tab`、详情定位 ID 等其他参数；禁止页面自行重复实现解析和序列化。

## 6. 数据库设计

- 真实语法以目标数据库和迁移框架为准，不默认使用 MySQL。
- 表名、字段名使用清晰一致的 `snake_case`；每张业务表使用稳定主键，关联字段明确写出业务对象。
- 金额使用定点小数或最小货币单位整数；时间必须声明时区语义，未另行约定时存 UTC；状态字段列明全部值及业务含义。
- 必填、默认值、唯一约束、关联/外键、删除策略和数据保留策略必须明确。索引服务于实际查询、排序、关联或唯一性，不创建等价重复索引。
- 敏感字段说明脱敏、加密、访问权限和日志策略；软删除、审计字段、幂等键和乐观锁在同一业务内保持一致。
- 表、业务字段、索引、约束、枚举、金额/比例单位、时间、JSON 和关键关联都必须有有效中文备注，禁止只写“名称”“状态”“时间”等无信息备注。
- 输出表设计时包含：用途与边界、字段清单、主键/索引/约束、关系与删除策略、DDL 或迁移代码、枚举/金额/时区/敏感数据/审计/幂等说明，以及高风险变更的兼容或回滚方案。

## 7. 实施与自检

1. 阅读入口文件、本文件及任务直接相关代码；涉及 UI 或工程环境时加载对应专题规范。
2. 检索可复用组件、API、类型、Service、样式和测试，明确输入、输出、权限、状态、失败路径与兼容要求。
3. 确定最小改动范围，实施并补充必要中文注释。
4. 按 `engineering-workflow.md` 执行与变更匹配的校验并报告结果和限制。

代码交付前确认：

- 命名、类型和职责清晰，无未使用代码、重复逻辑或危险类型绕过；
- 异步加载、异常、取消和重复提交按实际风险处理；
- 页面、Service、Adapter 与 API 边界清晰；
- 数据库设计完整说明单位、时区、枚举、索引、关联、敏感数据、审计、幂等和迁移策略；
- 涉及 UI 的实现通过 `ui-guidelines.md` 的对应检查，不在本文件维护第二套视觉规则。
