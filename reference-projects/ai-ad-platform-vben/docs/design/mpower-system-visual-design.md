# Mpower 全系统视觉设计规范

> 文档状态：待评审  
> 版本：V1.0  
> 适用范围：Mpower 后台管理系统（工作台、项目、素材、投放、数据、财务、资源、系统管理）  
> 视觉基准：工作台「素材任务详情」中的“浅蓝渐变概览 + 白底信息卡 + 紧凑数据块”风格

## 1. 设计目标

本次设计不是将“素材任务概览”机械复制到每个页面，而是把其视觉语言提炼为一套可复用的系统规范。目标是让用户在不同业务模块中获得一致的层级、密度和操作反馈，同时保留各模块自己的业务重点。

核心目标：

1. **信息一眼可扫**：页面先展示对象、状态和关键指标，再进入配置、列表或操作。
2. **复杂但不拥挤**：通过浅色画布、白色卡片、细边框和稳定间距承载高密度后台信息。
3. **重点足够明确**：蓝色只用于主操作、选中状态、关键指标和当前上下文，避免满屏高饱和色。
4. **全系统一致**：相同层级使用相同容器、圆角、字号、间距和交互状态。
5. **支持长期扩展**：新模块优先复用页面骨架和组件，而不是新增一套局部样式。

## 2. 视觉关键词

- 专业、克制、清晰
- 浅蓝科技感，但不过度装饰
- 低阴影、细边框、强层级
- 数据优先、操作明确
- 高信息密度、低认知负担

不采用：大面积高饱和蓝、重投影、玻璃拟态泛滥、过多渐变、每张卡片不同颜色、为了装饰而增加图形。

## 3. 信息层级模型

全系统页面统一使用以下阅读顺序：

```text
全局导航
  └─ 页面概览：当前对象 / 页面目标 / 状态 / 关键指标 / 主操作
      └─ 筛选或视图切换：决定当前数据范围
          └─ 业务区块：表格、表单、看板、图表或流程
              └─ 明细与补充信息
                  └─ 页面级或抽屉级操作栏
```

页面中不得同时出现多个竞争主视觉。每页只有一个概览区；普通业务区块统一使用白色信息卡。

### 4.3 圆角、阴影与间距

| 类型 | 规格 | 使用位置 |
|---|---:|---|
| 小圆角 | 6px | 标签、小型状态块 |
| 控件圆角 | 8px | 按钮、输入框、选择器 |
| 字段块圆角 | 10px | 指标块、只读字段 |
| 卡片圆角 | 12px | 普通业务卡片 |
| 概览圆角 | 16px | 页面或详情概览区 |
| 轻阴影 | `0 1px 2px rgba(15,23,42,.04)` | 普通卡片 |
| 抬升阴影 | `0 12px 32px rgba(15,23,42,.06)` | 概览、抽屉、弹窗 |

间距使用 4px 基础网格：4、8、12、16、20、24、32、40、48。禁止出现无规则的 13px、17px、27px 等间距。

## 5. 字体与数据排版

中文优先使用系统字体：`PingFang SC`、`Microsoft YaHei`；英文和数字使用 Inter 或系统无衬线字体。数字启用等宽数字特性，保证指标对齐。

| 层级 | 字号 / 行高 | 字重 | 用途 |
|---|---:|---:|---|
| 页面标题 | 24–28 / 1.25 | 650 | 概览主标题 |
| 模块标题 | 16 / 24 | 600 | 卡片标题、抽屉标题 |
| 关键指标 | 18–24 / 1.2 | 650 | 数量、金额、比率 |
| 正文 | 14 / 22 | 400–500 | 表格、表单、说明 |
| 辅助文字 | 12 / 18 | 400–500 | 标签、时间、字段名 |

规范：

- 页面标题尽量不超过一行，超长时省略并提供完整查看方式。
- 金额、百分比、数量、日期采用统一格式。
- 不使用纯黑文字；正文和标题分别使用 Slate 800、Slate 900。
- 弱信息不能只依赖更浅颜色，应同时通过位置、字号或标签区分。

## 6. 页面骨架

### 6.1 标准列表页

适用于任务中心、项目管理、素材库、投放列表、账号列表、审批列表。

```text
┌ 页面概览：名称 / 说明 / 关键指标 / 主操作 ┐
├ 视图切换或筛选卡                           ┤
├ 列表主体：表格 / 看板                       ┤
└ 分页与批量操作                              ┘
```

规则：

- 概览区与筛选区间距 16px。
- 筛选条件默认一行 3–4 项，窄屏自动换行。
- “新建”是唯一主按钮，其余使用次按钮或文字操作。
- 批量操作只在有选中项时出现，并显示已选数量。

### 6.2 详情页或全屏抽屉

适用于素材任务详情、投放任务详情、项目经营详情、工单详情。

```text
┌ 蓝色概览：对象 + 状态 + 4 个以内关键指标 ┐
├ 完整基础信息卡                            ┤
├ 业务明细卡 / 子项列表                    ┤
├ 交付记录 / 审批记录 / 操作日志           ┤
└ 吸底操作栏                                ┘
```

规则：

- 概览区只放影响判断的信息，不放所有字段。
- 完整字段必须进入“完整信息”卡，不因概览精简而丢失。
- 各业务区块纵向排列，默认不做左右两栏压缩；只有强关联信息可双栏。
- 底部操作栏吸底，背景为 96% 白色并带轻微模糊。

### 6.3 创建与编辑页

适用于新建素材任务、新建投放任务、新建项目、资源配置。

- 顶部使用紧凑概览式页头，展示“正在创建什么”和当前步骤。
- 表单按业务语义拆成卡片：基础信息、业务配置、需求明细、附件、确认。
- 每行最多 4 个短字段；标题、说明、附件等长内容独占一行。
- 必填标识、帮助信息、错误提示位置统一。
- 主操作固定为“保存并继续”或“提交”，次操作为“保存草稿”“取消”。
- 多步骤流程保留当前数据，不因前后切换丢失内容。

### 6.4 数据看板页

适用于首页、投放数据、素材洞察、人员产能、财务总览。

- 顶部概览区显示数据范围、更新时间和 3–4 个核心 KPI。
- 第二层使用 KPI 卡、趋势图、结构图；同层卡片高度一致。
- 图表颜色以蓝色为主序列，状态色只用于异常或目标差异。
- 图表上方统一提供日期、项目、平台筛选，不在每张图中重复筛选器。

### 6.5 配置页

适用于系统设置、平台配置、标签配置、规则配置。

- 左侧为分类导航时，右侧使用单列配置卡。
- 每张配置卡包含标题、用途说明、当前状态和编辑入口。
- 危险操作放在独立“危险操作”区域，不与保存按钮并列。

## 7. 核心组件规范

### 7.1 页面概览 Hero

这是本次视觉统一的核心组件。

结构：

- 左侧：图标、页面类别、状态、标题、上下文描述。
- 右侧：2–4 个关键指标块。
- 操作区：最多 1 个主按钮和 2 个次按钮。

视觉：

- 边框使用 Blue 200，圆角 16px。
- 背景使用左下白色、右上浅蓝的低对比渐变。
- 可增加一个透明度较低的径向蓝色光斑，不增加插画。
- 指标块为 76%–92% 透明白色，带 1px 白色边框。

约束：

- 指标最多 4 个；超过 4 个进入下方 KPI 区。
- 指标标签 12px，值 15–20px。
- 截止时间等长字段允许两行，其他指标优先单行。
- Hero 不用于普通卡片内部，也不允许一页出现两个。

### 7.2 信息卡

- 白色背景、1px Slate 200 边框、12px 圆角、轻阴影。
- 标题区高度约 48–56px，标题左侧可使用单色线性图标。
- 标题右侧只放帮助说明、查看全部或轻量操作。
- 内容区默认 16–20px 内边距。
- 相邻卡片间距 16px。

### 7.3 只读字段块

用于详情页完整字段展示。

- 浅灰背景、1px 边框、10px 圆角。
- 标签在上、值在下；标签 12px Slate 500，值 13–14px Slate 800。
- 空值统一显示“—”，不得留空或显示 `null`。
- 长字段可跨 2–4 列，但不得截断关键信息。

### 7.4 数据表格

- 表头使用 Slate 100，正文为白色。
- 行高建议 48–56px；复杂两行信息可使用 64px。
- 行悬停使用 Blue 50，选中行增加左侧 2px 蓝色标识。
- 第一列通常为对象主信息，采用“主标题 + 次信息”两行结构。
- 操作列固定右侧，默认展示 1–3 个高频操作，其余收入口袋菜单。
- 表格横向滚动时，关键列和操作列保持固定。
- 空状态必须说明原因和下一步，不只展示空图标。

### 7.5 表单控件

- 默认高度 36px，移动端 44px。
- 圆角 8px，默认边框 Slate 300。
- 悬停边框 Blue 300；聚焦使用 Blue 600 边框和半透明焦点环。
- 错误状态同时使用颜色、图标和文字，不仅改变边框颜色。
- 标签在控件上方；业务后台不使用浮动标签。

### 7.6 按钮

| 类型 | 使用规则 |
|---|---|
| 主按钮 | 每个操作区最多 1 个，如新建、提交、确认分配 |
| 次按钮 | 导出、刷新、保存草稿、批量修改 |
| 文字按钮 | 查看详情、编辑、进入子页面 |
| 危险按钮 | 删除、撤销、驳回；必须有明确文案和二次确认 |

按钮文字使用“动作 + 对象”，避免只写“确定”“处理”。例如“确认分配”“提交验收”“删除代理线”。

### 7.7 标签与状态

- 圆角 5–6px，字号 12px，默认不使用胶囊形大圆角。
- 状态标签颜色必须与系统状态映射表一致。
- 同一区域标签超过 3 个时折叠或换行，不能挤压主标题。
- 标签不代替正文，不承载长句。

### 7.8 Tabs 与分段切换

- 一级业务切换使用 Tabs，例如“素材任务 / 投放任务”。
- 同一数据的视图切换使用分段控件，例如“列表 / 看板 / 仪表盘”。
- Tabs 选中项使用 Blue 600 和 3px 下划线；不同时叠加蓝底和下划线。
- 标签名称必须是同一层级、互斥且完整的业务对象。

### 7.9 抽屉与弹窗

- 查看复杂详情使用全屏或宽抽屉，简单编辑使用中等宽抽屉。
- 会中断当前流程的确认使用弹窗。
- 抽屉正文使用 Slate 50 画布，内部使用白色卡片。
- 标题栏显示对象名称和编号；状态放在内容概览区。
- 弹窗按钮顺序保持一致：取消在左，主操作在右。

### 7.10 空状态、加载和错误

- 加载：保留页面结构，优先使用骨架屏，不让内容整体跳动。
- 空状态：说明“为什么为空”并提供一个明确下一步。
- 错误：在失败区域就地提示，提供重试；全局消息只作为补充。
- 无权限：说明不可操作原因，不简单隐藏导致用户误解。

## 9. 导航与系统外壳

- 左侧主导航保留深色背景，与浅色业务画布形成清晰分区。
- 当前菜单使用低饱和蓝灰背景和白色/浅蓝文字，避免大面积纯蓝。
- 顶部栏和页签栏使用白色或 92% 透明白色，可增加轻微背景模糊。
- 页签选中状态与业务 Tabs 区分：全局页签使用浅蓝底，页面内 Tabs 使用下划线。
- 主内容画布统一为 Slate 50，并在超宽屏限制内容最大宽度；数据大表可例外使用全宽。

## 10. 响应式规则

断点建议：

| 断点 | 适配方式 |
|---|---|
| ≥ 1440px | 内容最大宽度 1680px；指标可 4 列 |
| 1024–1439px | 标准桌面布局；筛选 3 列；指标 4 列或 2×2 |
| 768–1023px | Hero 左右结构改为上下；字段网格 2 列 |
| < 768px | 单列；控件 44px；按钮可换行或占满宽度 |

具体要求：

- Hero 在 1100px 以下由左右布局切换为上下布局。
- 只读字段网格在平板为 2 列，手机为 1 列。
- 表格不强行压缩全部列；保留关键列并允许横向滚动。
- 移动端吸底操作栏需避开系统安全区。
- 触摸目标最小 44×44px。

## 11. 可访问性规范

- 正文与背景对比度不低于 4.5:1；大号文字不低于 3:1。
- 所有可操作元素支持键盘访问，并提供清晰的 `focus-visible` 焦点环。
- 图标按钮必须有可读名称或提示，装饰图标对辅助技术隐藏。
- 状态不能只靠颜色表达，必须同时有文字或图标。
- 表单错误与对应控件关联，提交失败后焦点移动到第一个错误字段。
- 动画控制在 150–220ms；系统开启“减少动态效果”时关闭非必要动画。
- 图表必须提供文字摘要、数据表或可访问的关键结论。

## 12. 交互与动效

- 悬停：背景或边框轻微变化，不使用明显缩放。
- 点击：按钮可下移 1px，反馈立即发生。
- 卡片展开：180–220ms ease-out。
- 抽屉进入：保留系统默认方向动画，不叠加内容逐项飞入。
- 数据刷新：保留已有内容并显示局部加载，避免整页闪白。
- 成功操作：就地更新状态，同时显示简短成功提示。

## 13. 特殊页面与例外

以下页面使用同一套颜色、字体、控件和状态规范，但不强制套用标准卡片骨架：

1. **3D 导演台 / 画布编辑器**：属于沉浸式生产空间，保持深色或专用画布布局；只统一顶部导航、弹窗、按钮和表单控件。
2. **AI 对话 / 创作工作台**：保持对话和工作流所需的全高布局；概览区可压缩为紧凑页头。
3. **大型数据表**：允许全宽展示，不受普通内容最大宽度限制。
4. **登录与验证页面**：延续品牌色和控件规范，但使用独立认证布局。

## 14. 实施优先级

### P0：建立系统基础

- 全局颜色、文字、间距、圆角、阴影令牌。
- 页面画布、页面概览、信息卡、表格、表单、按钮、Tabs、抽屉规范。
- 统一状态色和状态文案映射。

### P1：高频业务页面

- 工作台任务中心及素材/投放任务详情。
- 项目管理及项目详情。
- 素材库、素材洞察、投放中心。
- 首页与核心数据看板。

### P2：支撑模块

- 财务中心、资源中心、审批、报表。
- 系统管理、平台配置、日志。

### P3：体验收口

- 空状态、加载、错误、无权限状态。
- 窄屏、键盘操作和对比度检查。
- 清理旧页面中的局部硬编码颜色与重复样式。

## 15. 设计验收标准

页面验收必须同时满足以下条件：

- [ ] 页面仅有一个明确的一级标题和一个主要操作。
- [ ] 当前对象、状态、范围和关键指标可在首屏识别。
- [ ] 详情页完整字段未因视觉精简而丢失。
- [ ] 相同层级的卡片、圆角、边框和间距一致。
- [ ] 普通强调使用蓝色，成功/警告/错误色仅用于状态。
- [ ] 空值、空状态、加载、错误和无权限均有明确表现。
- [ ] 1024px、768px 和手机宽度下无内容覆盖或不可操作项。
- [ ] 表格在窄屏可滚动，关键列和操作仍可访问。
- [ ] 所有主要流程可仅使用键盘完成。
- [ ] 焦点、悬停、禁用、错误、加载、选中状态完整。
- [ ] 3D 导演台等沉浸式工具未被后台卡片布局破坏。

## 16. 最终设计决策

全系统采用“浅色数据工作台”作为统一视觉方向：深色导航负责全局定位，浅灰画布承载业务，浅蓝渐变概览负责建立上下文，白色信息卡负责组织复杂数据。蓝色是唯一常规强调色，状态色严格按语义使用。

“素材任务概览”是这套设计的视觉母版，但不是所有内容的外观模板。后续页面应复用它的层级、密度、留白和信息组织方式，使系统统一而不单调。
