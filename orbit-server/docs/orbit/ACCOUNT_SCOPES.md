# 内部账户目录投影与范围冻结

## 输入字段与模式

ScopeRequestGuard严格接收产品ScopeRequest三字段：mode、account_ids、filter。IDS要求非空UUID数组且filter=null；FILTER要求空IDs数组和完整AccountSelectionFilter。原始IDs最多50000，先做数量检查，再将规范UUID排序去重。禁止客户端注入tenant、actor、members、name、external_id或任意SQL字段。选择对象只来自服务端目录。

过滤器五字段均须出现：q、status、auth_status、operator_user_id、vendor_id。q做NFC/首尾空白规范化，最多100码点且无控制字符；空字符串代表无名称筛选。status接受ACTIVE/DISABLED/UNKNOWN/null，auth_status接受AUTHORIZED/EXPIRED/REVOKED/UNKNOWN/null；投手与户商ID为规范UUID或null。未知属性、枚举和数字字符串类型不宽松转换。

名称搜索中的!、%、_转义为字面值；所有SQL值都参数绑定。名称模糊匹配，外部数字ID精确匹配，不将32位外部ID转long或浮点。状态、授权状态、投手和户商条件同时生效，再与当前数据权限求交集。显式IDS若有任一不可见/不存在账户返回404，不静默丢失；FILTER只冻结权限交集。

## 内部目录与一致性

V008建立目录投影、目录时钟、冻结头和冻结成员四表。投影只含选择需要的ID、名称、当前投手/团队/户商、币种、账户/授权状态及目录版本，不是完整Account DTO，不保存余额或凭据，也不播种生产示例账户。真实账户导入器尚未实现，生产目录初始为空。

目录source_state固定UNVERIFIED且有数据库约束，不能把fixture或未验证目录声明成可执行Meta账户。AccountDirectoryPublisher已补齐可信内部增量发布，使用与范围冻结相同的目录时钟行锁，原子更新目录成员及版本；真实Meta采集器、完整账户状态流与公开发布入口尚未实现。

冻结事务使用REPEATABLE_READ，锁定当前身份/显式管理团队、目录时钟及候选行，读取同一受控目录集合，再在同事务写头与成员。内部directoryRevision只是目录发布版本，**不冒充**产品公开scope_version；V009已增加当前已实现授权输入的独立权限时钟及冻结权限版本；未来模块授权源、公共DTO和游标消费端仍未接通。

## 冻结、重放与消费

自然幂等键为tenant/actor/requestKey，规范请求相同返回首次冻结结果，不同请求409。按账户UUID排序，冻结ID、外部ID、名称、目录账户版本并计算JSON UTF8 SHA256。成员每1000条分批写入，头/全部成员/ready一起提交；ready只表示完整冻结，不表示可执行。成员失败连同头和目录时钟预占回滚。

选择最多50000条，查询最多取50001条判断溢出，超过422而不是截断。空FILTER结果允许冻结，但空范围不可执行。元数据和成员保留冻结名称，后续目录重命名不会改写旧快照。

USER限当前operator_user_id为本人业务UUID；TEAM_ADMIN限显式管理团队；SUPER_ADMIN限当前授权租户。重放及消费重新读取当前身份、角色、显式团队摘要和每个当前账户权限。管理范围撤销、角色上下文变化、账户转给其他用户/团队或目录删除时拒绝旧快照，不靠旧成员放行。当前授权/状态及来源需在消费时再查；本阶段UNVERIFIED目录、已撤平台授权或空范围均不能执行。

## 内部目录发布事务

publishTrusted只接受服务端可信租户/当前用户、expectedRevision、最多1000项增量（更新与删除合计），没有HTTP入口。每次从数据库复核当前SUPER_ADMIN与有效租户上下文。空批次、重复账户或同一账户同时更新/删除拒绝；UUID、1—64位外部数字字符串、非空账户名（NFC、最多10000码点、无控制字符）、三位大写币种、账户/授权枚举严格校验。operator/team/vendor可为空；有投手时必须匹配当前有效成员和所属有效团队。户商这里只验证UUID格式，真实户商关系尚未接通。

锁住租户目录时钟后比较expectedRevision，不同返回409，防止迟到读取覆盖新发布；成功整个批次只推进一个目录版本，各更新账户使用同一新版本。新增和修改按账户UUID分别处理，外部ID唯一冲突不能更新另一账户。任何冲突、缺失删除或成员校验失败，已写入成员和时钟一起回滚。此内部入口没有请求幂等键；不确定提交结果后须先读取实际目录版本，不能盲目重试。

所有发布行强制UNVERIFIED，不能由调用者注入META_VERIFIED。重命名保留已冻结成员名称，删除或变更当前投手会令旧成员权限复核失败。并发冻结只能看见整个旧版本或整个新版本，不允许混合名称/账户版本。目录版本仍不是产品完整scope_version，内部发布成功不等于账户绑定或平台授权通过。

本轮新增7项真实MySQL用例：增改删与旧名称、并发CAS、外部冲突/晚期删除失败回滚、投手转移撤权、无效批次与迟到版本、角色/租户/归属撤销，以及发布和冻结并发的一致性。实际结果以evidence/account-directory-integration.json为准；没有增加完整需求验收勾选。

## 当前授权输入的单调权限版本

V009增加orbit_scope_version：每个租户从1开始，授权变更和版本递增在同一数据库事务提交；回滚一同撤销。最大9007199254740991，溢出由CHECK约束拒绝整个授权写入，不回绕。版本行不建租户外键，保留删除墓碑；重建相同租户UUID继续递增。重复运行迁移不重置已有版本，也不声称现有版本可用于所有未来模块。

数据库触发器覆盖当前已实现数据授权输入：orbit_user_scope、业务用户/团队/显式团队管理授权、规则草稿归属头，以及租户启停/删除、若依用户停用/删除。若依sys_role、sys_menu、sys_user_role、sys_role_menu可跨租户共享，修改时保守递增全部租户时钟。部分无权限影响的修改也会失效，版本不能作为业务修改次数统计。

账户目录新增、删除、投手/所属团队或租户改变递增权限版本；仅重命名、币种和平台授权状态变化不改变数据权限版本，相关当前状态依然在执行前重新验证。目录发布版本继续独立维护，不能互相替代。

ScopeVersionService在可信内部调用下读取当前有效身份并持共享锁；requireCurrentTrusted对无效版本422、当前身份失效403、跨租户404、权限版本不符409、缺少版本行503。没有HTTP端点，错误code及公开参数合同待公开接口实现，不以内部异常消息代替API合同。

范围冻结在同一事务写orbit_account_scope_permission、成员与头；缺少权限版本的历史快照不默认填1，重放409并要求重新生成。快照记录的是生成时版本，当前对象授权仍每次复核；这个记录本身不自动撤销缓存、SSE、导出文件，也没有完成公开游标验证。未来模板/接收人等新资源授权表必须接入同一递增协议。

本轮9项真实MySQL专项覆盖：撤权再授权不恢复旧版本；共享角色/菜单变更跨租户失效及回滚；成员/管理授权/登录停用；并发递增不丢失；账户归属与重命名差异及冻结版本；租户墓碑与重复迁移；安全整数溢出回滚；缺失版本/旧快照失败关闭；权限元数据写失败整笔冻结回滚。证据为evidence/scope-version-integration.json。它们不能替代公开接口、真实页面或全权限链验收。

本轮首测65项有1项失败：同一事务内JDBC变更共享授权后，MyBatis会话缓存使重复权限版本查询返回旧值。生产Mapper的权限版本SELECT已设置flushCache=true/useCache=false，保留原断言重跑；失败回执由MySQL执行器归档。当前读取不能依赖一次事务内的旧缓存值。

首轮失败归档：evidence/mysql-configuration-integration-2026-11-07T073727_0800.json（65项中1项失败，scopeVersionSharedRoleAndMenuChangesInvalidateAllTenantsAndRollback）。修复后完整65项通过，失败记录保留。

## 冻结成员分页核心（尚非公开HTTP接口）

ScopeMemberPager.pageTrusted只供可信服务端调用；tenant/actor不得直接取自公开请求参数。ScopeMemberPage按原合同仅包含items、next_cursor、data_as_of和scope_version；每个成员只含account_id、external_id、name。外部ID保留字符串，data_as_of是范围生成UTC时刻，scope_version是冻结时版本，不把当前账户名称或平台采集时间混入旧快照。

页大小只允许20/50/100/200。成员按规范账户UUID升序，游标使用最后一个UUID做keyset分页，一次最多读取pageSize+1项判断是否有后页，末页next_cursor=null。q先NFC/strip、最多100码点且禁止控制字符；匹配冻结名称的字面子串（!/%/_转义）或外部ID精确值，不使用当前目录名称过滤旧范围。

每次读取先验证当前有效身份及该actor自己创建的快照。目录共享锁与发布器协调，以当前身份/accessHash及锁定的数据库权限版本证明整份冻结范围授权未变；版本变化时全范围当前读复核，不能只校验本页；撤销角色、显式管理团队、投手/团队归属或删除范围中任何账户都会拒绝。无数据权限404；权限版本变化409（首屏也须重新冻结，旧幂等键不会重绑定新快照）。没有权限版本的历史范围409；缺少当前版本服务503。返回页面不授予执行权，目录仍UNVERIFIED。

游标复用服务端独立AES-GCM keyring，以tenant/snapshot/purpose+actor作AAD，绑定格式版本、after、成员hash、权限版本、规范q及页大小。游标不包含可读名称或外部ID，长度上限2048，篡改/截断/错误类型/跨快照或用户/改变q或页大小均422，不返回解密异常细节。主密钥未配置时503，不降级明文或可伪造的Base64游标；密钥轮换依赖保留所需旧key_id。未擅自增加产品未定义的固定TTL。

公开POST创建和GET成员及CSRF扩展已连接，详见[SCOPE_HTTP.md](SCOPE_HTTP.md)。HTTP层已落实会话、当前菜单授权、错误边界、CSRF及完整ASCII幂等键；字段HTTP反例、受控跨租户正向授权和UI仍需继续验收。选择弹窗、跨页全选前端、取消旧查询和业务保留策略仍待实施；不能把本核心当成完整API已验收。

### 分页容量检查后的优化与身份版本补强

初次5万成员250页测试通过，但每页全范围反连接重复扫描。稳定版本路径改为：当前有效身份与accessHash一致、目录共享锁、数据库权限版本共享锁且版本等于冻结值，才以完整授权证明直接读取该页；任何版本变化仍查询整份范围，当前有成员不可见404，否则409要求重新冻结。依赖数据库原子触发器协议，不依赖JWT缓存、客户端版本或上一次请求的授权结果。真正执行前的逐账户权限/授权/状态/来源校验不走此优化。
