# Meta 多应用绑定验收记录

日期：2026-11-10。范围：后台应用管理、授权时选择应用、原生登录浏览器会话及来源隔离。不是整个产品全部功能完成声明。

## 已验证

- 后端完整测试：6299 通过。
- 前端完整串行测试：108 文件、1386 用例通过。最终增加目录不完整提示后，相关 3 文件、40 用例通过（含 2 个新增回归用例，先失败再修复）。
- TypeScript 检查及生产构建通过；最终回调说明 UI 的相关 13 用例另通过。
- 真实 MySQL / Redis / HTTP 集成：72/72 通过。覆盖并发领取、来源版本、事务与审计回滚、原令牌消耗、多应用隔离、重授权、撤销、异步采集恢复。Meta 外网响应使用明确隔离的测试替身，不能据此宣称真实客户授权成功。
- gstack 隔离环境：真实原生登录、浏览器会话转换、绑定应用字段、两个应用的选择、选定应用授权会话创建、桌面与手机布局检查通过；未跳转虚构应用执行真实 Meta 授权。
- gstack 线上：管理员登录、绑定表单字段、Meta 入口成功打开。管理员自行补全邮箱后业务身份校验通过；无应用时显示配置提示并禁止连接。未向生产写入测试应用或凭据。
- 安全复核：应用配置范围的取消授权隔离、停用与修改来源失效、旧令牌撤销、会话转换中退出竞态已有覆盖。

## 发布与迁移

生产使用独立版本目录；先备份数据库，执行 076_meta_application_selection.sql，再切换 API 和前端。原版本及服务配置保留。迁移使原生会话可明确不关联 OIDC 提供者，同时为授权会话与连接保存应用配置 UUID 和版本。

新环境按已有部署说明安装依赖、顺序执行未应用迁移、配置数据库/Redis/认证加密主密钥/PUBLIC_ORIGIN。Graph API 版本必须明确，当前支持配置 v24.0。构建 orbit-web 并部署静态产物，重启 API，检查 readiness。秘密只进入受控配置，不进入源码。

## 剩余外部验收

用户需在生产后台绑定真实 Meta 应用及企业登录配置，并在 Meta 设置固定 OAuth 回调。完成应用角色、只读权限、发布或审核后，由实际账户主体执行授权，核对账户及真实 Insights 数据。此记录不将内部模拟、空连接列表或 UI 授权链接创建视为真实 Meta 授权/数据对账通过。

业务资料不完整时须补全真实邮箱及角色目录；不填造假邮箱、不绕过身份校验。应用秘密和 Token 不在报告或截图中出现。
