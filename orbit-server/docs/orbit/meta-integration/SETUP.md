# Meta读取接入配置与联调

## 交付边界

该接入只读取账户、广告结构与统计数据。连接成功、身份匹配、`ads_read` 或报表采集成功均不授予广告创建、预算修改等写能力。真实平台验收必须在应用、域名及权限就绪后单独执行；隔离测试不能替代 Meta 审核或客户授权。

## 平台应用

在 Meta 开发者后台创建归属平台企业的应用，添加适用的 Marketing API 与 Facebook Login for Business 用例。应用配置、权限名称及可用 API 版本以创建时后台为准。

- 域名：`drmovira.com`。本轮不修改 DNS 或部署服务。
- HTTPS 必须具有受信证书；前端路由及 `/api/v1/` 反向代理到本平台。
- 严格匹配 OAuth 回调：`https://drmovira.com/api/v1/integrations/meta/callback`。
- 取消授权回调：`https://drmovira.com/api/v1/integrations/meta/deauthorization`。
- 数据删除回调：`https://drmovira.com/api/v1/integrations/meta/data-deletion`。
- 提供真实隐私政策、服务条款、支持联系方式和数据删除说明页面；本代码不伪造这些运营资料。
- 创建 Business Login 配置，授权类型为后端授权码交换；本轮请求读取权限 `ads_read`。枚举 BM 资源需要 `business_management`。配置中不要加入本轮不需要的 `ads_management`。
- 对外客户使用前完成相应权限的高级访问申请、企业验证及应用审核。准备演示账户、操作录像和最小权限用途说明：连接、候选选择、归属与渠道、数据同步、断开及删除请求。
- 开发模式只用于应用角色成员的内部联调；不能据此宣称任意客户已可授权。

官方参考：[Meta Marketing API集合](https://www.postman.com/meta/facebook-marketing-api/collection/0zr4mes/facebook-marketing-api-mapi)、[官方Business SDK](https://github.com/meta/facebook-python-business-sdk)。开发者文档访问限流时，必须在应用后台复核所选版本字段，不默默选“最新版”。

## 服务端受控配置

沿用当前项目受控私有配置加载器，仅增加以下变量，不写入仓库、不放前端环境变量：

| 变量 | 用途 |
| --- | --- |
| `ORBIT_META_APP_ID` | 平台统一应用ID |
| `ORBIT_META_APP_SECRET` | 平台应用密钥，仅服务端使用 |
| `ORBIT_META_GRAPH_VERSION` | 显式Graph版本，当前字段合同已核验 `v24.0`；其他版本明确拒绝，没有默认值 |
| `ORBIT_META_LOGIN_CONFIG_ID` | Business Login配置ID |
| `ORBIT_PYTHON_PUBLIC_ORIGIN` | `https://drmovira.com`，用于浏览器同源校验 |

原独立AES-GCM主密钥配置和浏览器会话/OIDC配置必须先就绪。客户Token按租户与连接ID加密；界面只返回状态，不能回读明文。不要把密钥粘贴到聊天或命令历史。生产访问日志必须省略OAuth回调查询串，不能记录请求正文中的签名回调、授权码或Token；应用中间件也会移除回调查询串。

## 管理员BM接入

在原系统配置保存BM ID、与平台兼容的Graph版本和系统用户凭据。管理员从该配置发起接入。服务端验证凭据所属应用、主体、读取权限与有效期，并完整枚举该BM下owned/client账户。填写BM ID或原“只读测试通过”不代表账户接入成功。配置被关闭或更新后，旧版本来源停止使用，必须重新验证。

## 数据库与启动

先备份并审核目标环境，按现有迁移顺序执行新增071、072、073、074、075（分别为授权连接、采集检查点、导入来源、连接指标口径、采集策略）。应用不自动迁移；本轮只对独立测试库执行迁移。保留原账户、归属、当前渠道、实体快照与指标事实表。

采集调度默认关闭。先完成应用配置、归因指标配置验证、单账户人工联调与数据对账，再按租户显式启用调度。Worker应与Web进程分开管理，异常退出后从持久检查点恢复，不靠内存计时器。

## 真实验收步骤

1. 登录平台，具有 `system.integrations.manage` 的用户连接Meta；验证取消、拒绝权限、过期state和重新授权。
2. 候选必须来自服务端枚举。选择账户，保持投手、团队、户商、渠道字段；接入仍需原账户导入及归属权限。
3. 首次采集近90个账户业务日。同一账户、日期、币种和归因配置，导出Ads Manager结果逐项对账。未知与缺失显示空值，不用零值掩盖失败。
4. 检查异步报表、分页、进程重启、部分失败和迟到旧任务；失败不能覆盖已发布数据。
5. 重新授权、断开、撤权后旧任务停止；原业务历史仍可按既有权限查询。
6. 测试签名取消授权及删除回调。删除请求即时废止凭据，并返回跟踪确认码；`PENDING` 表示历史数据清理流程仍待完成，不能展示已清理。
7. 用gstack验证授权入口、候选、归属、渠道、同步状态、数据页和手机布局。

## 当前外部阻断

平台Meta应用尚未创建；域名之前检查未能解析。没有完成DNS/HTTPS、应用配置与权限审核前，不开展真实客户OAuth成功声明。用户仍需在Meta页面亲自完成登录/二次验证；不要提交密码、Cookie、验证码或Token给开发助手。


## 只读任务进程

受控私有配置还需 `ORBIT_PYTHON_META_WORKER_ENABLED=true` 与 `ORBIT_PYTHON_ACCOUNT_CURRENCIES`（JSON数组，例如 `["USD","EUR"]`；须按实际允许币种配置，示例不代表全部支持币种）。默认不开启进程；数据库租户调度仍另行显式开启。

在后端目录执行 `.venv/bin/python tools/run_meta_read_worker.py --once` 单轮，或 `--serve --interval 30 --limit 10` 常驻。支持正常信号停止和数据库租约恢复。不接受Token、连接字符串或私有配置路径作为命令行参数。此进程串行执行原导入Worker、账户元数据同步、首次90日回填、已启用的调度及指标任务消费。

首次接入需要先发布并选择指标口径；如尚未就绪，账户元数据可保留，指标采集不会用默认归因值冒充完成。所有金额分币种保存，账户业务日窗口包含当地今天。

## 指标口径与各连接采集设置

在系统管理的METRICS配置中发布已验证口径：选择对应Meta连接、转化事件映射、归因窗口和报告时间。随后在连接列表的“采集设置”选择该连接的口径。每个连接可独立启用定时采集，默认关闭；已有租户默认策略只应用于未配置连接策略的账户，连接策略关闭时不会回退启用。不同客户的连接不能借用彼此的口径证明或凭据。

广告数据页可选择包含历史数据的具体口径版本；旧版本失效或连接断开不会删除已发布历史。历史查询仍检查账户、归属与数据范围权限。查询缺失、不完整或失败时显示实际状态。
