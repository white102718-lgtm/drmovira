## 大数据量架构与验收门槛

MySQL8承担强事务主数据和命令状态，Redis负责有限缓存/会话/通知，不保存唯一业务结果；失败恢复以数据库为准。大事实表不与账户/权限表混作一个通用集合。素材文件保存对象存储，数据库只存元数据和校验摘要。

| 范围 | 实施约束 | 必须留存的验证 |
| --- | --- | --- |
| 事务列表 | tenant前缀复合索引、稳定第二排序键、20/50/100/200游标分页；不做深OFFSET | 各筛选组合EXPLAIN ANALYZE、首/中/末页稳定性与权限变化409 |
| 统计事实 | 账户业务日/IANA时区、外部ID字符串、Decimal金额/币种分别汇总；原始事实与日/小时增量汇总分层 | 重复和迟到数据幂等、汇总对账、未知不补零、UTC/业务日边界 |
| 分区与归档 | 按业务时间设计分区及冷热保留；唯一键/幂等键需符合MySQL分区约束，不能只添加分区语句 | 分区裁剪计划、跨分区查询、唯一性、历史恢复和归档后引用可读 |
| 异步任务 | 同步/导入/AI/导出后台执行，批次有上限，任务状态持久化；业务/版本/幂等/审计/outbox同事务 | 并发重试、进程中断恢复、重复投递、取消、UNKNOWN核验与内存上限 |
| 报表 | 查询必须带授权租户及有界时间窗，在线聚合优先走汇总；列式分析库作为可替换读取适配层 | MySQL结果对账、汇总版本水位、P50/P95/P99/超时/错误率 |
| 缓存 | tenant+actor/数据角色+scope版本+筛选+数据版本为键；撤权不能等待缓存TTL后才生效 | 同Token撤权、跨租户/跨角色污染、缓存击穿/热键、命中与未命中一致 |

首批容量夹具计划覆盖5万账户/范围及100万统计事实，分开记录冷/热查询、并发、峰值内存、数据库版本和机器配置。这是待执行验收规模，不是已通过容量承诺。旧Java的5万成员250页测试只作迁移参照。更大规模或分库分表以可复现瓶颈和执行计划为依据，不预先宣称横向扩展已实现。
