# 原合同保留章节（只读基线）

以下为原包详细合同摘录，未以摘要替代字段、指标、流程与异常信息。若出现已删除的独立模块入口/资源申请流程，仅由01文档的删除边界覆盖；不授权删除保留页面中的字段。开发应同时读取本摘录与01修订需求、完整字段字典及保留版OpenAPI。原合同P/D/E来源标记原样保留，不重新声称用户批准。

## 3 统一指标与数据语义

所有金额保留原币种；删除币种下拉不代表可以直接相加不同币种。P：自动化单计划只允许同币种账户；监测页按币种自动分组金额卡和表格金额，不提供币种选择器；跨币种 ROAS 不合并成单值。若后续引入换算，另建汇率版本和显示口径，未启用前不得隐式换算。

界面所有时区统一使用 UTC±HH:mm，例如 UTC+08:00（上海）。同一偏移的地区可保留地区名，以区分夏令时规则。时区格式变化只改变展示，不把所有账户时区强制改为 UTC+00:00。涉及历史、未来运行点时按该时刻计算偏移；仅展示当前配置时用当前偏移。API持久化继续保存规范IANA值，并返回offset_at和display_label；服务端不得把显示文本当调度时区。

存储 UTC 时间戳和账户 IANA 时区；日事实用账户当地 business_date。跨账户报表的日期表示各账户同名业务日，而非相同 UTC 区间；UI 简短标注“账户当地日”。事件日志按用户时区展示、ISO8601 导出。调度时区独立于指标账户时区。

|指标|计算与缺失规则|来源|
|---|---|---|
|消耗 spend|Decimal 原币种；缺失 null；0 是有效零|Meta Insights spend|
|展示 impressions 与点击 clicks|计数；clicks 为全部点击，不能与链接点击混用|Insights 同名字段|
|注册 registrations|按 metric_profile 选定唯一事件 action_type，未配置返回 null|Insights actions；自有注册仅作为另一个来源|
|购物 purchases|同一归因口径下指定 purchase 事件；不得将 omni、website、pixel purchase 相加|Insights actions|
|购物价值 purchase_value|与购物事件同范围的价值|Insights action_values|
|ROAS|sum(purchase_value)/sum(spend)；消耗为0或任一质量条件不满足时 null|服务端计算；不平均各行 ROAS|
|CPM 千次展示费用|sum(spend)/sum(impressions)*1000；展示0返回null|服务端计算；列名不得简写为展示量|
|CTR|sum(clicks)/sum(impressions)*100；输入阈值用百分数，例如1表示1%|服务端计算|
|CPC CPA|消耗/点击；消耗/指定转化数；分母0为null|服务端计算|
|回流收入|自有订单或回流系统的独立财务口径|不可直接重命名为 Meta 购物价值|

metric_profile 冻结来源、action_type、归因窗口、action_report_time、时区和 breakdown 组合。事实主键必须含 metric_profile_id。不能将各归因窗口或国家/年龄细分行与总计重复求和。reach、frequency、unique_clicks 不可直接跨广告求和；有需求时使用对应层级平台报表。

API 空结果不能一律记为零：须区分完整查询且无投放、权限变化、拉取失败、返回字段缺失、尚未处理。只有完整批次的有效零才可进入规则。记录 completeness、freshness、coverage 和 watermark；比较窗口必须口径相同。

### 4.1 广告账户管理

服务端分页默认50，最大200；按账户名、完整 ID、投手、状态筛选；300ms 防抖并取消旧查询。所有分页返回 scope_version 与 data_as_of。显示账户名称/ID、所属户商代称、授权、状态、币种、UTC格式时区、同步时间；所属户商以账户归属关系关联户商代称，户商改代称后当前列表同步，历史日志保留当时快照。余额、应付账单、总花费分列并注明来源。balance 不映射为可用余额。未知或无权限字段显示“未知/未授权”，不能填0。

授权通过服务端 OAuth，账户列表必须来自授权资产。允许本地解绑以停止采集与控制、保留历史；与向供应商申请解绑分开。重新分配投手在账户当地下一业务日00:00生效，创建日期有效区间，不修改历史事实；即时停止写权使用撤权，不制造日内业绩拆分。

### 4.2 自动化投放

步骤1 选择账户：标题、搜索、仅看已选和当前筛选选择在同一卡片；搜索不清空选择。跨页全选必须显式生成服务器选择快照及数量，不能把“本页全选”伪装为全部。批量最多500账户/计划（P），超过拆分。

步骤2选择启用且媒体为Meta的投放渠道，再构建系列→广告组→广告树。渠道选项来自渠道管理；当前离线原型仅示例Meta通道，其他媒体按实际连接器能力另行启用。

步骤2至4 构建系列→广告组→广告树。每层复制只复制配置，不复制平台 ID、执行状态和凭证。任何配置、账户、素材、预算或能力版本变化使原预检失效。广告预算实际归属系列或广告组；广告层不写 daily_budget。

步骤5 素材选择、组合和分配冻结 seed、material_revision 与 allocation_id；同一预览提交产生完全相同的分配。素材已删除、处理中或被隔离不得使用。创建数量公式为各账户求和，再对每系列的份数乘各组份数乘各广告份数累加；不要把不同系列全局做笛卡尔乘积。预算合计按真正预算拥有者和复制份数累加，不对每条广告重复计系列预算。

步骤6 预检返回逐字段错误、按账户的对象数、预算拥有者、币种、计划 hash 及过期时间。确认提交仅受理该 hash。按钮 pending 防重复，后台 Idempotency-Key 去重。创建 DAG 为上传素材→系列→组→创意→广告→回读；可独立并发的节点受账号配额控制。父节点失败，子节点 BLOCKED_DEPENDENCY，独立分支继续。

保存草稿允许不完整配置，但结构、长度、租户和大小仍须合法；提交必须全部必填。服务器草稿为准，本地只存不含凭证的恢复缓存。保存失败显式提示“未保存”，不更新成功时间。模板不保存账户选择、凭据、环境租约、外部 ID 或执行结果；加载后重新选择账户和身份资源并预检。

### 4.3 执行任务和投放统计

任务页分“正在执行”“历史记录”。QUEUED/RUNNING/VERIFYING/UNKNOWN/RETRY_WAIT 在进行中；终态成功、失败、部分成功、取消进入历史。未知结果不能自动当失败并重建。取消只阻止未发送节点，已发送节点继续核验。

失败提醒显示账户、节点、阶段、可读原因、平台错误码、发生时间、建议处置、重试资格。技术详情收起，不显示凭据。提醒与任务终态独立持久化，转入历史不消失。

投放统计只保留汇总及趋势：已核验广告数量、消耗、曝光、点击、购物、价值和 ROAS。创建数量以 tenant+account+external_ad_id 去重，广告ID回读成功才计数；部分任务只计成功节点。统计以自动化来源映射连接事实，不统计所有账户广告。效果窗口默认按投放数据业务日，展示创建数与成效日期口径。不得恢复创建与成效明细表。

### 4.4 广告投放数据和规则建议

主 Tab 为监测与规则优化、投放师、渠道、广告账户、广告系列、广告组、广告。渠道位于投放师之后，查询口径与渠道报表一致。规则命中对象卡内把标题、系列/组/广告子 Tab、记录/采纳统计放一起，Tab 徽标按当前权限和筛选下待处理数量计算。空、加载、错误、无权限分别有状态。

命中表必含对象名/ID、账户名/ID、投手、消耗、ROAS、点击、注册、购物、购物价值、CPM、命中规则/时间、AI建议、本次建议和处理状态。表格指标跟随当前筛选；建议详情必须显示生成时冻结窗口与版本，不能用新表格数值冒充旧建议证据。

规则命中后自动排队分析；页面无“开始分析”按钮。分析失败按策略自动重试，详情可见失败原因。查看分析依据、修改建议、忽略及批量提交可用；修改后保留原AI建议。观察建议不可提交执行。提交前展示匹配对象与实际预算目标及影响范围；共享预算相同目标和相同金额合并，不同金额冲突阻止提交。

操作记录保存匹配系列/组/广告名称和ID的快照、本次优化建议、实际操作、提交和核验时间、操作人、结果、错误及实际目标。对象改名或删除后历史仍可读。手工操作标为“无AI建议”。

采纳统计按预算修改、关闭、删除分类，预算可细分增加/减少。分母为指定生成日期队列内的可执行建议，排除观察、分析失败、未提交且被替代或已过期的建议；已提交建议永久保留分母；每建议只计一次。原样/修改以提交快照判定。原样采纳、修改后采纳、忽略、未处理分别计数；采纳率=(原样+修改后)/可执行建议。执行成功率=已核验成功建议/已提交建议，未知显示待核验。一个命令合并多个建议时，建议数和命令数分别展示；提交失败不算成功，重复重试不重复采纳。

### 4.5 规则 素材 报表 审批及环境

规则编辑把作用对象放名称下方，模拟与保存并启用固定底栏。每日窗口起止字段不存在；保留整体生效日期、运行频次、时区。规则不预设执行动作。

素材筛选桌面两行：搜索/分类/标签关系/标签；日期/指标上下界/排序。没有币种下拉。上传后病毒与媒体校验→处理→可用；原型伪图片须替换实际预览。批量删除为内部逻辑删除，不调用 Meta 删除历史素材；整批提交前锁版本和任务引用，冲突整批不删。对象文件保留策略默认30天（P），有历史证据引用则延长。标签停用不清除历史引用。

投手报表支持汇总/按日、投手和日期，币种分组无选择器。按账户分配历史算归属。导出异步、按授权范围、审计和到期下载；CSV 防公式注入。

【范围修订：此独立资源审批流程已移除；其他页面只读金额与信息保留。】

AdsPower 页面列出机器、客户端/API连通、Profile运行、代理探测、Meta登录、账户身份匹配、能力、心跳、租约及最近故障。系统管理配置人员、角色、账户范围、集成凭据引用、阈值和审计；原型身份切换器在生产移除。

### 4.9 渠道投放命名与报表

REQ-CH-01：创建广告必选投放渠道；系列名格式为渠道名称_用户昵称_YYYYMMDD_自动编号，例如星河美国投放_林晓_20261030_0001。昵称未配置时回退用户姓名，渠道名称未配置时回退渠道ID（P）。日期按Asia/Shanghai业务时区生成并在界面显示UTC+08:00，不能使用浏览器机器时区。

编号P：按租户+渠道ID+用户ID+业务日分配，至少4位、超过9999自然扩位；对展开后的每个账户和每份系列分配独立编号。数据库序列事务保留、允许跳号、不得回收；并发或重试不重复。原型为浏览器本地序列，不能保证跨用户设备全局唯一。生成后只读，不要求用户手填。

选择渠道或账户、系列复制份数、昵称/渠道名或命名日期变化，原预览失效；重新分配和预览后冻结全部最终系列名。相同预览提交和任务重试沿用相同序号与名称；规则与执行幂等键仍使用ID和hash，不用名称。渠道停用或权限变化在提交前复验。

每计划、展开系列、广告、任务节点保存channel_id、channel_name_snapshot、channel_code_snapshot、product_snapshot、nickname_snapshot、naming_date和最终campaign_name。Meta创建请求name使用冻结名称；对象创建成功后以真实ad_id建立渠道归属。不能按名称正则反推正式渠道。任务失败、部分成功和UNKNOWN不丢归属证据。

REQ-CH-02：左侧新增渠道报表；广告投放数据的主Tab顺序为监测与规则优化、投放师、渠道、广告账户、广告系列、广告组、广告。两处渠道视图共享同一查询与指标口径，不能分别写不同汇总逻辑。系统管理菜单置于最后。

报表支持日期、渠道、投放师和渠道名称/ID/产品搜索；列为渠道名称/ID、总代、产品、媒体、账户数、广告数、消耗、展示、点击、注册、购物、购物价值、ROAS、CPM。金额按币种分组、时间按账户当地业务日，归因profile按第3章冻结。账户数/广告数均对当前范围事实中的ID去重；无事实不假定为0投放。ROAS和CPM按分子分母重算。

未知历史渠道单列“未归属渠道”，不得把整账户所有广告归给当前所选渠道；同一账户多渠道按广告归属拆分。注册/购物未映射时显示未知，不能代用全部转化。渠道改名后当前管理标签可更新，历史执行证据及产品归属按快照保存；历史统计口径更正需有版本、依据和审计。

渠道报表只读权限与导出权限独立，查询始终带tenant与授权账户范围；渠道未停用不意味着其所有账户都可读。数据新鲜度和缺失数随查询返回。分页/大范围异步查询遵守第11至12章。

### 4.10 全局UTC时区交互

REQ-TZ-01：账户列表/详情、户商二级页、产品列表/详情/编辑、下户申请、规则调度、分析依据和其他弹窗都使用UTC±HH:mm。例UTC+08:00（上海）、UTC-04:00（纽约）、UTC+00:00。地区名仅用于区分相同偏移，禁止显示层替换数据库时区值。

下拉option的label为UTC格式，value仍为地区时区标识；选择、保存、刷新保持一致。夏令时地区在冬夏日期可显示不同偏移，例如纽约冬季UTC-05:00、夏季UTC-04:00。未来运行列表每一行按该次运行时刻算偏移，同时提供UTC+00:00对应时间。账号历史报表按业务日规则计算，不能因UTC显示变更整体平移业务日。

前后端应提供统一格式化函数并接收reference_at，避免用当前偏移解释历史事件。格式化只作用时区展示字段及语义明确的标签，不修改用户文案、链接、Token、程序代码或API参数。当前原型使用统一DOM展示转换，生产应在组件和数据格式层实现，避免任意文本替换。

## 5 字段约束的统一规则

以下为生产开发合同，不表示原型已实现。每条字段的必填条件在提交时适用；草稿允许缺少业务必填，但类型、最大长度、文件大小和结构上限始终生效。下拉框不允许用户自由填写未知值；远程选项每页50，搜索上限100字符，失效选项显示原值并要求重选。

文本长度按 NFC 规范化后的 Unicode code point 计算，前后端使用同一方法；trim 只去首尾空白，正文保留内部换行。短输入拒绝换行，长文本允许LF；禁止NUL及不可见控制字符，保留合法 emoji。中文字符和英文字符都计1，emoji组合可能计多个码点，UI需一致计数。必填空白视为缺失。所有文本按纯文本输出并转义，不允许 HTML 执行。

金额API采用十进制字符串加currency，写平台时用经过校验的最小单位整数；禁止float乘100后直接取整。数字拒绝NaN、Infinity、科学计数法字符串和空值隐式转换。服务端校验错误返回字段路径、错误码、约束及中文说明；保留输入、聚焦首个错误；异步错误不能清空表单。

只读外部字段没有用户最短/最长输入行为，存储应容纳平台原始值；若平台名字超出本产品编辑上限，保留原值、显示省略、编辑时明确限制，不截断同步数据。平台约束比产品更严格时使用更严格约束，并显示原因。控件的HTML属性仅为辅助，不能替代API与数据库约束。

## 6 规则计算与触发合同

规则 AST 只允许两层条件组，指标和操作符均使用白名单；不得执行用户代码或拼接SQL。三值逻辑：AND 中有 false 则 false，否则有 unknown 则 unknown；OR 中有 true 则 true，否则有 unknown 则 unknown；仅 true 产生候选命中。null != 0 不是 true，而是 unknown。

调度器使用数据库租约和到期队列；每次run绑定 rule_revision、schedule_slot、scope_snapshot、data_snapshot、metric_profile。INTERVAL以生效日当地00:00为锚点递增实际分钟；DAILY/WEEKLY以当地墙钟执行，DST不存在时刻跳过并写日志、重复时刻只执行一次。生效与截止日均包含；停用或超期不能新建分析任务。调度停机后合并错过的周期，仅计算最近一个有效slot，记录遗漏，不对旧时段突发补执行。

试运行与生产运行共享 evaluator。模拟返回授权账户数、实际扫描对象数、命中/不命中/未知数、逐条件观察值、缺失原因和快照hash；不调用模型或外部写接口。启用要求当前revision的成功模拟，P 有效期15分钟；修改任意条件、范围、时间、保护参数使模拟失效。不能用固定演示 A/B/C 代替。

去重分两层。评估幂等键为 tenant+rule_revision+entity+schedule_slot+snapshot_version；分析冷却键为 tenant+rule_id+entity，按冷却和当天额度原子检查。周期内重复消息不重复计费；同一天同一观察窗口有新数据，可在冷却后分析，不能按“日期窗口唯一”永久抑制。规则新版本不能绕过租户级分析费用总额。

一次事务写 rule_hit、analysis_job、outbox；发布器将 outbox 事件投递到队列，消费者以event_id幂等。至少一次投递加幂等，不声称消息恰好一次。过期、数据不完整、归因口径变化先记录 SKIPPED/UNKNOWN；不得发送空值伪造的分析。

持续命中处理：首次创建待分析项；新快照而旧建议尚未提交时，按冷却生成新分析版本并将旧建议 SUPERSEDED；已提交或已忽略建议不覆盖，保留其证据；已忽略后新命中生成新建议。旧任务晚到结果不能覆盖更新版本，按WORKFLOWS.md处理。处理状态和分析状态分别存储，避免“已核验”被新分析改回待处理。

## 7 数据采集与 AI 接入运行

### 7.1 数据怎样进入系统

Meta采集Worker按租户和账户授权获取对象与Insights；原始响应先存对象存储，附请求字段、日期、版本、分页游标、返回时间与校验hash。所有页完整成功后提交同步批次；部分失败不发布“全量完成”。标准化服务解析金额、事件类型和时区，生成事实版本与批次watermark；持久化完成后发 data.snapshot.ready，规则引擎才处理。

P 刷新策略：1000个重点活跃账户每15分钟，其他活跃账户每60分钟，休眠账户每日；不是每个用户各拉一次。更高优先级用于执行后回读，低优先级为历史补数。当天和近7日滚动重采；每日补采8至28日，超28日按归因配置及差异任务重采。平台配额或权限不足时延迟并标记stale，不能伪造最新时间。

如果接自有订单/注册数据，采用独立 authenticated ingestion 接口：event_id唯一、event_time、received_at、account/ad映射、金额币种、撤销事件。服务端验签、防重放、权限和时间范围校验；不把个人姓名、邮箱、电话送入模型。不能因有Meta CAPI就假设可读到逐单归因；CAPI是上报转化的另一个方向，本项目读取报表不需要把规则命中发给Meta。

### 7.1A 户商导入与渠道数据接入

户商账户导入接口从路径取得vendor_id，接收account_ids_text和允许指派的拥有者字段，不让用户填写账户名或消耗。服务端先校验租户、户商平台、操作者权限及凭据资产范围，再按第10章读取Meta账户元数据与Insights；不将户商联系人或账户ID本身当成授权凭据。账户导入只创建内部绑定，不创建Meta广告账户、不充值、不改变Meta资产所有权。

内部ad_id→channel_id关系由计划与执行快照写入，Insights提供投放指标而非本系统渠道维度。采集后按真实ad_id关联渠道，再构建channel_daily聚合；历史补数沿用对应归属版本，不以当前账户渠道替换历史。客户、产品、包和总代是业务维度，未确认时不能把KPI文本、费率或Token直接发送模型。

### 7.2 规则命中如何上报分析

内部事件不是浏览器调用LLM。outbox事件只携带受控引用，分析服务凭服务身份读取限定快照，校验tenant和对象归属，再构建指标包。最小字段如下：

|事件字段|类型与约束|用途|
|---|---|---|
|event_id schema_version trace_id|UUID；版本1；UUID|去重、追踪、兼容|
|tenant_id rule_id rule_revision hit_id|UUID；UUID；正整数；UUID|绑定命中和不可变规则|
|account_id entity_id entity_type|内部UUID；UUID；CAMPAIGN/ADSET/AD|对象范围|
|schedule_slot occurred_at|带时区ISO8601|调度位置和发生时间|
|snapshot_id metric_profile_id evidence_ref|UUID；UUID；受控引用|取数，不传任意URL|

分析输入提供当前窗口、等长前窗、近7/28日趋势、数据新鲜度、覆盖率、归因成熟度、对象年龄、预算归属、预算变更历史、状态、同素材表现、投放频次（仅在来源可用时）。最多28日逐日点与100个贡献子对象（P），大系列其余对象聚合为others；不得给LLM五万账户全量明细。数字由指标服务计算，LLM不能自行修改分子分母。

### 7.3 模型服务和边界

模型供应商采用服务端Adapter：输入schema→可信系统提示→脱敏事实包→模型调用→JSON Schema校验→证据与数值校验→策略校验→建议落库。供应商和模型版本配置化，不在浏览器保存API Key。先建立固定回归数据集，选择满足质量、延迟和成本标准的模型，再锁定版本。无需为本阶段接入指定供应商私有API；开发测试使用可控fixture。

模型输出 action=OBSERVE/BUDGET_SET/PAUSE/DELETE，target_entity_id、budget_owner_id、before/after、currency、reason、evidence_ids、risks、data_quality、policy_version、model_version。reason长度20至2000字符；evidence_ids至少1且必须存在输入；OBSERVE不得含执行金额，BUDGET_SET必须包含金额及拥有者，非预算动作after=null。输出禁止未知字段、SQL、代码、URL或执行工具调用。可用低/中/高的证据充分程度，不能用未经校准的“95%成功概率”。

确定性风控优先于模型：缺权限、关键指标缺失、快照超期、口径不一致、预算拥有者不明→OBSERVE或BLOCKED。P 新数据快照超过30分钟禁止执行建议，超过采集SLA标记过期；归因成熟度不足不因低ROAS给删除建议。新广告观察期默认24小时；跨币种不共用金额阈值。预算单次变化默认不超过20%，24小时累计上调不超过30%，同时受租户金额上限约束；财务负责人需在上线前确认。

DELETE只能对已暂停、已满足保留期和成熟数据门槛的对象形成候选，P 默认暂停至少72小时；仍须人工确认和 delete权限。删除系列/组必须展示子树影响，不能因一个低效广告自动删除整个系列。关闭或删除不等于账单立即停止变化，历史归因会继续更新。

AI不能：调用Meta或AdsPower、访问凭据、扩大账户范围、决定审批、绕过预算上限、伪造缺失数据、承诺收益、把相关性当因果、执行创意文本中的指令。广告名称和文案是非可信数据，不拼进系统指令；结果展示统一转义。模型故障、非法JSON、证据不存在、金额越界都不输出可执行建议。

P 每次模型请求超时60秒，最多重试2次，指数退避并抖动；并发和每日Token/费用预算按租户限制。模型不可用时建议显示分析失败/稍后重试；确定性规则只可给“观察/需复核”，不能冒充AI。页面关闭后任务继续。

### 7.4 分析评价与投放效果

离线验收集不少于300例，覆盖三种对象、稀疏/迟到/缺失、零消耗、共享预算、不同币种、冲突、提示注入和删除边界。硬性越权/非法动作通过率要求100%；数字引用一致率100%；结构化结果有效率>=99%；其余进入失败状态。建议合理性由至少两名投放负责人抽审，记录分歧；采纳率不是唯一模型质量指标。

建议落库冻结模型、prompt hash、policy、输入快照、输出和成本，支持按版本回滚。执行后按同口径等长窗口观察，区分执行成功、效果改善和因果增益；因果收益需要对照试验，不能只用前后ROAS差判断。删除与停止广告仍跟踪迟到转化。

## 8 执行反馈与一致性

命令状态：DRAFT→VALIDATED→QUEUED→RUNNING→ACCEPTED→VERIFYING→SUCCEEDED。发送前失败可到FAILED；网络超时且不知平台是否接收则UNKNOWN；可安全重试则RETRY_WAIT；用户取消未发节点则CANCELLED。父任务汇总PARTIAL_SUCCESS，节点保留独立结果。

提交事务生成command与outbox；幂等键为tenant+业务操作UUID，payload_hash不同但键相同返回409。Worker按账号限流，按预算拥有者/对象树冲突集合串行化，使用持久化租约和fencing_token；过期Worker的本地回写拒绝。外部平台不一定识别fencing，所以租约失效后不能立刻重复外部写，先对账。

发送前再次取平台配置，比较冻结的预算、状态、父级和授权。Meta未提供本系统本地revision的原子CAS保证，因此外部其他工具仍可并发修改；读前写后降低风险，不能承诺消除跨工具竞态。发现不一致中止并要求重新预览；执行后漂移触发提醒，不自动反复覆盖别人修改。

接口成功只说明受理或对象生成。保存external_id、fbtrace_id（如返回）、请求/响应hash、平台错误code/subcode、attempt和时间。后台GET回读对象id、account_id、父级、creative、预算、configured_status、effective_status等；字段符合目标才标配置核验成功。广告审批中、父级暂停或账户问题要独立显示，不能把配置ACTIVE等同实际投放。

P 回读退避5、15、30、60秒，随后最长15分钟；超时转UNKNOWN并入对账队列，每5分钟重查直到24小时，再人工处理。该策略受配额限制，不保证平台15分钟内生效。删除后“读取不存在”还可能是权限失效，必须结合提交回执、权限仍有效及平台语义证明；单独404/权限错误不能标成功。

创建遇到响应丢失不能凭相同名称找到对象就认领，也不能盲目重建。优先使用已持久化external_id或平台可验证关联字段；无唯一证明则UNKNOWN且人工核对。已确认没有发送的请求可以重试。修改预算用绝对目标值并回读，避免重复“增加10%”叠加。平台batch子请求各自成功失败，不能当数据库原子事务。

对用户反馈：提交后立即返回operation_id；前端通过SSE订阅任务进度，断线凭last_event_id续传，轮询为降级。后台事件为事实来源。错误分为配置错误、权限失效、限流、平台暂时错误、环境离线、身份不符、结果未知和依赖失败；显示可操作的中文原因，详情含脱敏错误码。

## 9 AdsPower 环境监测方案

AdsPower Local API 提供Profile运行状态和浏览器调试连接；GET /api/v1/browser/active?user_id=... 返回Active/Inactive，GET /api/v1/browser/local-active 返回本机打开的Profile。v2对应GET /api/v2/browser-profile/active使用profile_id/profile_no，需支持该版本的客户端。Active只证明浏览器进程打开，不证明Facebook登录、广告账户权限或广告操作成功。[S6 S7]

部署本地Agent在每台运行AdsPower的机器。Agent主动使用mTLS与云端控制面连接，云端不直接访问用户localhost。Local API Key留本机密钥存储；API和调试WebSocket端口不暴露公网，也不转交前端。MCP若采用，仅是封装本地能力的适配层，不自动提供Meta身份或业务回执。

|层级|探测方法|状态和处置|
|---|---|---|
|Agent|每15秒主动心跳，带seq和boot_id|45秒无新心跳SUSPECT，90秒OFFLINE；恢复需连续2次正常|
|Local API|受控本地地址连通和鉴权；返回code与耗时|UNREACHABLE/AUTH_FAILED/READY，不能只看HTTP200|
|Profile|local-active批量和必要时active单查|ACTIVE/INACTIVE/UNKNOWN；正常关闭不是故障|
|浏览器通道|仅自有租约Profile的CDP连接探测|断连DEGRADED；不重新操控别人任务|
|代理网络|经配置代理访问允许的探测地址|记录可达、延迟和出口变化；不等于Meta身份有效|
|Meta登录与身份|只读页面状态或受授权接口核验，匹配所需账户ID|LOGIN_REQUIRED/CHALLENGE/IDENTITY_MISMATCH/VALID；验证挑战交人工|
|执行能力|按版本验证所需定位器/读写合同|UNSUPPORTED时阻止UI执行，不猜坐标点击|
|租约|agent+profile独占租约、过期、fencing|BUSY/OWNED/EXPIRED；禁止两个任务共用一个Profile|

新任务在获取租约后执行完整预检，最长60秒（P）；中途环境失败先停止新的动作，已提交动作转UNKNOWN等待业务核验。监测不为查看5万账户而启动5万个浏览器。API通道无需AdsPower；优先Meta API，UI通道只覆盖已明确授权且能力测试通过的操作。

监控轮询按机器限流，开放Profile用批量接口，非活跃Profile按需查询。官方文档列出的2/5/10次每秒随Profile数量和版本变化，且部分接口1次每秒；这些不是全平台统一吞吐保证。Agent启动读能力配置，保守默认1次每秒；达到配额排队，不绕过限流。[S6]

UI创建/优化反馈：记录operation_id、目标Meta账户及对象ID、前置状态、提交动作和可用回执；成功toast只作为辅助证据。具备Meta读权限时必须用Graph API回读核验；无读权限则状态为SUBMITTED_UNVERIFIED或UNKNOWN，展示需要人工核验，不能仅靠截图宣布成功。任何UI输入发现账户身份不符、验证码或权限墙都停止。不开启规避平台风控的自动化。

字段转换：country_codes→targeting.geo_locations.countries；age_min/max→targeting同名；locales→语言ID列表；网站pixel_id与事件→promoted_object.pixel_id/custom_event_type；应用application_id与商店URL→promoted_object对应字段。自动版位和归因枚举由能力包生成，禁止把中文自由文本直接发平台。

Insights 请求标准字段：account_id、campaign_id、adset_id、ad_id、date_start/date_stop、account_currency、spend、impressions、clicks、actions、action_values。购物/注册从actions按metric_profile指定action_type映射，购物价值从action_values匹配；保存原始数组。ctr/cpc/cpm/purchase_roas可供对账，但展示的汇总比率重算。默认不加breakdown；有细分需求用独立dataset，避免总计重复。

本版新增字段的接口边界：账户名称、状态、币种、时区等读取GET /act_{account_id}，当日消耗读取GET /act_{account_id}/insights?level=account&time_range=账户当地日&fields=spend,account_currency，具体可用字段仍按版本权限验证；数据库保存account_id不带act_，仅在Graph路径适配。户商代称、客户、产品、渠道名称、渠道归属、内部自动编号均来自本系统，不向Meta查询。最终系列名写入campaigns的name字段；渠道ID与元数据在内部冻结，不伪造Meta存在channel_id字段。

马甲包归因平台是独立连接器；Token与AppsFlyer/Adjust等服务的认证、事件获取、归因对账和时效需单独联调。本版不承诺已有对应外部接口，不猜测供应商endpoint。尚未接入时明确显示未配置/未同步。

外部不存在直接对应接口的字段：本地投手、审批意见、模板、规则、采纳统计、AI解释、任务状态、租约、告警都在本系统；“个号名称”“可用余额”“付费方式”不保证Meta统一提供，使用授权的供应商/业务维护来源并标注。充值、回收、下户不能承诺由Marketing API完成。

授权对接：服务端生成一次性state，验证回调来源和redirect_uri，服务端交换凭据并存KMS引用。记录scope、资产范围、expires_at及最近校验；撤销/到期停止新写操作并提醒。日志脱敏，不把Token放浏览器或提示词。服务端请求设置超时、按app/business/account的配额桶自适应调速，读取实际限流响应与usage headers；不硬编码“每账户固定每小时N次”。

Webhook仅在锁定版本已支持并配置相应订阅时作为变更提示；验签、快速入队、event去重，随后GET核验。不能假设所有广告操作都有可靠Webhook，更不能把所有Insights增量建立在Webhook上。核心反馈以请求记录加回读对账为准。

### 11.2 亿级事实模型

canonical_daily_fact的粒度是tenant+account+entity_type+entity_id+business_date+metric_profile_id+breakdown_key。首期无breakdown，ad层是主汇总来源；系列/组指标从广告可加指标聚合，非可加指标另用对应层级平台数据并以dataset区分。禁止把ad、adset、campaign三个层级相加。

每次重采发布绝对值版本，source_version由每个采集范围的任务generation及批次序列保证单调；提交时拒绝落后于已发布generation的旧请求，较晚完成的旧请求不得覆盖更新请求。保留observed_at、batch_id、quality、is_deleted、原始对象引用。ReplacingMergeTree(version)按排序键去重是后台最终过程，查询不能假设旧版本立刻消失。[S9]

正确性优先的默认方案：原始响应对象与不可变批次清单用于追溯，ReplacingMergeTree只保留可合并的版本并最终淘汰旧行；规范视图按完整粒度argMax(tuple(metrics,quality,is_deleted),version)取最新，tuple保留null语义，再过滤删除；受影响账户+业务日期重算日聚合和规则指标快照，发布完成后原子切换可查询snapshot_id。大量历史分区采用离线重建和分区替换，避免对亿级数据频繁小UPDATE。

严禁把重复的绝对值快照直接接SUM增量物化视图：先写100后补数120会错误累加为220。若选增量差分方案，必须由可靠的旧值状态生成+20、以event_id去重并测试迟到/重放；首期采用重算受影响范围的可审计方式。ClickHouse增量视图处理插入块，不会因为源表后台去重自动回撤旧聚合；可刷新视图能重算，但不能每15分钟重算全部亿级表。[S10]

分区按业务月，排序建议(tenant_id,account_id,metric_profile_id,business_date,entity_type,entity_id,breakdown_key)；账户维度查询命中排序前缀。跨账户仪表盘读tenant/day/currency汇总表，避免5万个账户逐个join。分片按tenant+account哈希以分散单大租户，分片内副本保持一致；单分片够用时先少分片，依据压测扩容。不要每个账户建分区或表。

汇总层：account_daily、operator_daily、campaign_daily、adset_daily、asset_daily、launch_cohort_daily、rule_metric_snapshot。预计算可加分子分母，展示时算ROAS/CPM。对象归属快照随事实记录或以有效期维表处理，避免当前owner重写历史。

存储保留P：原始响应90天在线、之后冷归档；明细热层180天、冷层最多2年；聚合2年；操作审计2年，法务/客户要求另行确定。删除用户/租户需覆盖缓存、队列、对象存储和备份到期策略，不仅数据库删一行。

### 11.3 查询路径

账户列表读PostgreSQL索引和游标；账户名模糊检索按实际模式用pg_trgm或专门搜索服务，禁止对50000行每次无索引ILIKE加复杂join。投放明细先限定tenant、日期、账户与层级，再查ClickHouse，分页最多200；排序字段白名单，排序值+ID为复合游标。任意指标排序跨长时间范围采用物化查询结果或异步任务，不能深OFFSET扫全表。

缓存键包含tenant、scope_version、metric_profile、currency grouping、from/to、filters、sort、published_snapshot。短缓存30至60秒（P），权限撤销立即失效；响应标记as_of。不同权限或归因口径不得复用缓存。导出与UI使用同一口径，独立低优先级队列，下载链接15分钟有效。

## 12 容量 性能和可靠性验收

100用户解释为100个注册且最坏100同时在线；容量测试采用100并发活跃会话。5万个账户不等于5万个广告：假设平均每户200条活跃广告即1000万条；每条每天一条事实，10天就是1亿行。若每小时全量存储则约2.4亿行/日，因此默认保存日事实的版本更新和重点账户短期小时数据，不承诺所有广告分钟级全量历史。

采集计算：1000重点账户每15分钟=约1.11个账户任务/秒；其余49000每小时=约13.61个任务/秒，合计约14.72任务/秒。若每任务平均5页，则约73.6个数据页请求/秒，另加异步创建、轮询、元数据、补数和重试。这只是流量估算；App/Business/account配额若不支持，必须降低频次或限定重点集合，不能靠增加数据库节点解决。

存储估算P：假设每逻辑行压缩后120字节，1亿当前事实约12GB，仅为数据体；若平均3个版本、2副本、再预留3倍给索引/汇总/合并空间，总量约216GB，未含原始响应与素材。实际压缩比、列数、TTL及合并放大必须用真实分布样本测量。

起始压测配置候选：PostgreSQL主备各8vCPU/32GB；ClickHouse 2分片×2副本，每节点16vCPU/64GB/NVMe；3节点持久队列；API和Worker分别自动扩容。此为测试起点而非采购承诺；单分片也可能足够，依据扫描量和CPU结果缩减或扩容。100个用户本身不是选型依据，查询形状、活跃广告量和同步频率更重要。
