## 身份、权限与会话

外部身份以经过验证的 issuer 原文及 sub 原文共同确定。邮箱只用于邀请接收者核验，不能自动合并人员。权限来自本地有效角色与当前数据范围，不接受提供者返回的租户、角色或团队替代本地授权。

Cookie 名称沿用原合同 adpilot_session。会话随机凭据只存分用途摘要；浏览器绑定凭据单独校验。会话闲置上限 30 分钟，绝对上限 12 小时；续期不得延长绝对上限。服务端核对人员、团队、租户、身份安全版本及登录配置版本。退出只撤销对应会话，重放相同幂等键返回原回执；审计失败必须回滚状态。

生产 Cookie 使用 HttpOnly、Secure、SameSite=Lax、Path=/，不设置 Domain。请求上下文不得跨并发或异常请求继承。Cookie 写请求校验来源和 CSRF；旧 Bearer 兼容路径仍执行原有校验，不能因兼容分支跳过认证。

## 一次性授权与邀请

授权事务保存 state 和浏览器绑定摘要，verifier、nonce 与返回地址使用独立 AES-GCM 信封。五分钟内一次性认领，网络交换前提交认领状态；交换结果不明时不得再次使用原授权码。

邀请有效期 24 小时，绑定人员版本、身份安全版本、邮箱快照和提供者版本。重发在同事务撤销旧邀请。回调必须验证接收邮箱已被 IdP 证明；绑定、人员启用、业务版本、会话、审计与事件一起提交，任何一步失败不得留下半个已激活账号。

邀请凭据不能出现在管理接口响应或日志。投递队列保存加密载荷；只有真实渠道接受响应才记录 ACCEPTED，不能把入队或 HTTP 成功声称为邮件已送达。发送后超时记 UNKNOWN，人工重发生成新邀请并撤销旧凭据。

## 数据量、索引和清理

会话按 token_digest 唯一定位；身份按 issuer/sub 摘要定位后比较原文。邀请和授权事务按状态、到期时间、ID 小批游标清理。人员邀请历史按租户、人员、创建时间、ID 查询，禁止深 OFFSET 或读取全表。事务持锁期间不得等待外部网络。容量指标另行实测，不以单条查询或小夹具宣称通过容量验收。

## 验证边界

存储专项可以预置已验证身份夹具，但只能证明存储事务。完整 OIDC 验收必须经过实际签名、公钥验证、一次性授权码、PKCE 和浏览器 Cookie 往返；不能预置映射后声称登录成功。隔离服务与现有 18080/18081 预览分别运行。

协议依据：[OpenID Connect Core ID Token Validation](https://openid.net/specs/openid-connect-core-1_0.html#IDTokenValidation)、[OAuth 2.0 Security Best Current Practice](https://www.rfc-editor.org/rfc/rfc9700.html)。
