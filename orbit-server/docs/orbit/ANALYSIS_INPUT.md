# AI分析输入与限制合并核心

## 本阶段实现

`AnalysisInputGuard`校验可信随包JSON Schema 2020-12：完整字段白名单、必填、UUID/日期/时间格式、字符串十进制与规模约束；格式断言显式开启。依赖固定为networknt 1.5.9，配置依据为[该版本官方说明](https://github.com/networknt/json-schema-validator/blob/1.5.9/README.md)。运行时只读取本地可信Schema，不接受用户Schema或外部ref地址。

新增配置：输入最多逐日点0—28（默认28）、输入最多证据1—500（默认500）、建议最大输出Token256—32768（默认4096）。前两者只允许收紧产品Schema上限；Token区间沿用已有提供商配置边界，与具体模型能力验证分开。

校验核心要求事实包tenant_id与服务端可信租户一致；拒绝重复证据ID、非小写SHA256证据ID、重复业务日和超过1的coverage。全局/规则冷却取较大值、日分析上限取较小值、策略/提供商输出Token取较小值。实际模型上限仍须Adapter验证。

合法输入转为键顺序稳定的JSON字符串和SHA256，金额继续保留十进制字符串，调用后修改原JsonNode不会改写已生成的输入串；toString不打印事实包。校验错误只返回固定安全文案，不拼接被拒绝值或Schema错误详情。

## 产品Schema正则修正

原始`data`和`docs/orbit/baseline`完全保留。产品analysis-input.schema.json的十进制正则小数点重复转义，导致合法小数被拒绝。仅随包运行时副本修正pattern的小数点转义；其余类型、字段、required、长度、枚举、数组上限保持原样。对照测试把原Schema按同一明确补丁规范化后与运行时资源逐节点比较，另验证六位小数通过、七位小数拒绝。
