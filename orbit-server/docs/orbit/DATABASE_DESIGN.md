## 大数据量约束

- 小型配置/权限表优先可读性与完整事务；大事实表通过内部紧凑关联键降低重复外部ID与UUID的索引成本。外部ID及业务UUID在接口始终规范字符串，不因性能改成可能丢精度的JavaScript数值。
- 金额使用Decimal/DECIMAL；未知保留null，记录来源、观察时间与币种，不能为加速混币种求和或把未知补0。
- 时间统一UTC存储，账户业务日按IANA时区。时间分区的全部唯一键需满足MySQL规则，分区/归档/引用完整性一起设计，不能先分区后丢失幂等约束。
- 热路径不扫描多年事实表；在线报表先查可追踪水位的汇总。数据延迟/部分未知明确返回，原始事实可回溯核对；不能伪造实时完整。
- 游标绑定筛选、排序、水位和scope版本；改变过滤或撤权必须失效。索引优化不能通过删租户、团队或所有权条件获得速度。
- 导入/采集/AI/导出使用有界批次和持久任务，流式读写；失败恢复从水位继续，结果不能仅在Redis。
- 缓存键包括租户、角色/身份、授权版本、过滤和数据版本；跨租户缓存污染、撤权后旧缓存、击穿/热键均需测试。
