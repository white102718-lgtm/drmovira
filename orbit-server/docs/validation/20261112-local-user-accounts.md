# 人员直接创建、开启/停用与登录密码（2026-11-12）

## 已实现的当前行为

按用户本轮确认，“充值密码”指重置登录密码，不新增充值业务。

- 新增人员默认开启；输入真实姓名、昵称、邮箱、手机号、团队、角色和登录密码。手机号作为登录账号，全局唯一；管理员已有账号保持原账号不变。
- 创建即建立原生登录账号、密码哈希、身份主体及租户/团队/角色映射，无邀请或邮件验证步骤。也可创建为停用状态。
- 人员状态只有开启、停用。历史未完成邀请人员显示停用，先设置密码再开启；不会自动生成或猜测其密码。
- 列表补充登录账号、团队名称、功能角色、密码状态；操作为详情、编辑、开启/停用、重置密码。编辑联系方式不会更改已有登录账号。
- 密码与确认密码一致后提交；密码 8—64 字符且 UTF-8 不超过 72 字节。服务端 bcrypt 单向哈希；响应、审计、幂等响应不包含密码。敏感幂等意图用带密钥摘要验证，保存摘要密钥版本支持轮换。
- 管理员重置密码后旧密码失效，身份版本递增，旧会话失效。重置不擅自开启停用账号。本人和基础管理员使用个人中心修改密码；企业 OIDC 身份仍由身份提供者管理密码。
- 状态、角色、密码操作保留真实服务端权限、租户范围、版本冲突、幂等和同事务审计。不能停用自己或破坏最后管理员存续。
- 邀请发送接口退役，返回 410 `INVITATION_RETIRED`；既有有效邀请在迁移时撤销，保留历史记录。

## 接口与迁移

- `POST /api/v1/users`：原人员字段增加只写 `password`，status 为 ENABLED / DISABLED；phone 为新账号登录名。
- `POST /api/v1/users/{id}/password`：正文仅 `{password}`，需当前权限、CSRF、Idempotency-Key 与带引号 If-Match。
- 人员查询响应增加 `login_account`、`team_name`、`role_names`，不允许将这些展示字段提交到更新接口。
- 先执行 `079_local_user_credentials.sql`：敏感幂等记录增加密钥版本、原生用户名唯一索引、撤销旧邀请。执行前检查原生用户名重名，不能任意合并历史身份。
- 服务端备份相关表与 API / Nginx 配置；发布目录 `/opt/orbit/releases/20261112-local-users`。旧静态资源继续保留，刷新页面使用新表单。
